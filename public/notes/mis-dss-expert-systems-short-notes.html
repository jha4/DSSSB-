MIS, DSS and Expert Systems — Complete Notes

Coverage: Information systems, transaction processing, office automation, MIS, decision support, expert-system architecture, OLTP and batch processing.

1. Information systems overview

An information system combines people, processes, data and technology to collect, process, store and distribute information for operations and decisions.

2. Management Information Systems

MIS is an organized system providing timely, relevant and accurate information to support planning, control and decisions. It commonly transforms operational data from transaction systems into management reports.

  • Input: transaction and operational data. Processing: validation, aggregation and analysis. Output: reports, dashboards and alerts. Feedback/control: helps monitor performance and correct deviations.
  • MIS is effective for routine, structured information needs; it does not replace managerial judgement.

3. Decision Support Systems

A DSS is an interactive system that helps decision-makers analyze alternatives, especially for semi-structured or unstructured problems.

  • Data management subsystem: database and DBMS for relevant data.
  • Model management subsystem: analytical models, simulation, forecasting and optimization.
  • User interface/dialog subsystem: lets users interact with data and models.
  • Some frameworks include a knowledge-based component; exact component lists vary by textbook.

What-if analysis changes assumptions to see consequences. Sensitivity analysis measures how results change when assumptions vary. DSS supports decisions; it does not necessarily make the final decision.

4. Expert systems

An expert system emulates aspects of human expert reasoning in a limited domain using explicit knowledge representation and an inference procedure.

  • Knowledge base: facts, rules and domain knowledge.
  • Inference engine: applies rules to facts. Forward chaining starts from facts; backward chaining starts from a goal/hypothesis.
  • User interface: supports interaction. An explanation facility may describe how a conclusion was reached. A knowledge engineer helps capture domain expertise.

Expert systems are domain-specific and depend on the quality/completeness of encoded knowledge; they do not possess general human understanding.

5. OLTP and batch processing

  • OLTP: Online Transaction Processing; handles many short, concurrent transactions with emphasis on consistency and response time.
  • Batch processing: collects jobs/transactions and processes them together at scheduled times or in groups; useful for payroll, billing and bulk operations.
  • OLTP is interactive and transaction-oriented; batch processing is job/group-oriented. Both can coexist.

6. Exam traps

  • TPS records transactions; MIS summarizes information; DSS supports analysis; expert systems encode specialist rules.
  • DSS supports semi-structured decisions; it does not guarantee an optimal decision.
  • Inference engine applies rules; knowledge base stores domain knowledge.

DSS architecture and model base

A Decision Support System (DSS) assists a person or group with semi-structured or unstructured decisions. It supports judgement; it does not replace the decision-maker or guarantee a correct decision.

ComponentRoleExamples
User interface / dialog subsystemLets users enter assumptions, run analyses and inspect resultsDashboards, forms, scenario controls
Database / data-management subsystemStores and retrieves internal/external dataSales, inventory, market data
Model base / model-management subsystemStores and executes analytical modelsForecasting, optimization, simulation, what-if analysis
Knowledge base (where included)Stores rules or expertise to guide analysisBusiness rules, constraints, recommendations

What-if analysis changes input assumptions to observe outcome changes; sensitivity analysis studies how output responds to changes in selected inputs; goal-seeking works backward from a target output to find required input values. The model base is distinct from the database: one stores analytical procedures/models, the other stores data.
