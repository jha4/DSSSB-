2. Operating System fundamentals

Definition and objectives

An Operating System is system software that acts as an interface between users/applications and computer hardware. It manages resources and provides services to programs.

  • Convenience: makes the computer easier to use.
  • Efficiency: uses CPU, memory and devices effectively.
  • Resource management: allocates and releases resources.
  • Protection: isolates processes and controls access.
  • Abstraction: hides low-level hardware details.

Main functions

FunctionResponsibility
Process managementCreate, schedule, synchronize and terminate processes.
Memory managementTrack, allocate, protect and reclaim memory.
File managementCreate, organize, read, write and delete files.
Device managementControl devices through drivers and I/O subsystems.
SecurityAuthentication, permissions and protection.
User interfaceProvide CLI or GUI.

Types of operating systems

  • Batch OS: executes grouped jobs with little/no interaction during execution.
  • Multiprogramming: keeps multiple jobs in memory; CPU can run another job when one waits for I/O.
  • Time-sharing: allocates CPU time slices for interactive use.
  • Multitasking: supports multiple tasks through scheduling and context switching.
  • Multiprocessing: uses multiple processors or cores.
  • Multi-user: supports concurrent users.
  • Distributed OS: coordinates resources across multiple computers.
  • Network OS: provides network services such as shared files and printers.
  • Real-time OS: designed to meet timing constraints; hard real-time deadlines are critical, soft real-time misses may be tolerable.
  • Embedded OS: designed for dedicated devices.

Important comparisons

ConceptsDifference
Multiprogramming vs multitaskingMultiprogramming emphasizes CPU utilization; multitasking emphasizes responsive concurrent task execution.
Multiprocessing vs multitaskingMultiprocessing uses multiple processing units; multitasking can time-share one CPU.
Hard vs soft real-timeHard deadlines must not be missed; soft deadlines are desirable but occasional misses may be tolerated.

Kernel, shell and drivers

  • Kernel: privileged core of the operating system.
  • Shell: command interpreter/interface.
  • Device driver: software that controls a hardware device.
  • System utility: maintenance and management program.

3. OS structure and system calls

Kernel architectures

  • Monolithic: most OS services execute in kernel space. Linux is a modular monolithic kernel.
  • Microkernel: keeps only essential mechanisms in kernel; more services run in user space. MINIX 3 is a common example.
  • Hybrid: combines design approaches; Windows NT is commonly described as hybrid.
  • Modular: supports separately loadable kernel modules.

System calls

A system call is the controlled interface through which a user program requests a kernel service.

CategoryExamples
Process controlfork(), exec(), wait(), exit()
File managementopen(), read(), write(), close(), lseek()
Device managementDevice request/release and device operations
Information maintenancegetpid(), time(), system information
Communicationpipe(), socket(), send(), receive()

Important Unix calls

  • fork() creates a child process.
  • exec() family replaces the current process image with a new program.
  • wait() waits for a child process state change/termination.
  • exit() terminates a process.
  • open(), read(), write(), close() manage file descriptors.
  • lseek() changes the file offset; it does not itself read or write file data.
  • sleep() suspends execution for a specified duration.

fork() return: negative = failure; zero = child; positive = parent receives child PID.

User mode vs kernel mode

User modeKernel mode
Restricted privileges; applications commonly execute here.Privileged execution; kernel controls protected resources.
Requests services through system calls.Can execute privileged instructions.

A mode switch does not necessarily imply a process/context switch.

4. Process management and threads

Process vs program

A process is a program in execution. A program is passive code; a process is an executing entity with state and allocated resources.

Process Control Block (PCB)

The OS maintains a PCB for each process. It commonly stores:

  • Process ID and process state.
  • Program counter and CPU registers.
  • CPU scheduling information.
  • Memory-management information.
  • I/O status and open-resource information.
  • Accounting and ownership information.

Five-state process model

StateMeaning
NewBeing created.
ReadyWaiting for CPU.
RunningCurrently executing on CPU.
Waiting/BlockedWaiting for I/O or an event.
TerminatedExecution has ended.
  • New → Ready: admitted.
  • Ready → Running: dispatch.
  • Running → Ready: preemption/time slice expires.
  • Running → Waiting: requests I/O or waits for event.
  • Waiting → Ready: event/I/O completes.
  • Running → Terminated: exit.

Job queue contains submitted jobs; ready queue contains processes waiting for CPU; device queues contain processes waiting for devices.

Context switching

Context switching saves the current execution state and restores another process/thread's state. It involves saving registers/program counter, selecting the next runnable entity and restoring its context. It is overhead: the CPU does not perform useful work for the switched user processes during the switch itself.

Process vs thread

ProcessThread
Has its own address space and process resources.Execution path within a process; shares process address space/resources.
Separate processes usually communicate through IPC.Threads communicate through shared process memory.
Creation/context management is generally heavier.Usually lighter-weight.

Threads in one process share code, data, heap and many process resources. Each thread has its own stack, registers, program counter and thread ID. User-level threads are managed by a user-space library; kernel-level threads are managed by the OS.

Schedulers

  • Long-term scheduler: admits jobs into the system/memory.
  • Short-term scheduler: selects the next process for CPU.
  • Medium-term scheduler: suspends/swaps processes out and later brings them back.
  • Dispatcher: transfers CPU control to the selected process.

A zombie is a terminated process whose exit status has not yet been collected by its parent. A process waiting for I/O is normally blocked, not ready.

5. CPU scheduling

Objectives and formulas

  • Maximize CPU utilization and throughput.
  • Minimize turnaround, waiting and response time.
  • Provide fairness and avoid starvation.
MeasureFormula
Turnaround time (TAT)Completion time − Arrival time
Waiting time (WT)TAT − CPU burst time (for the standard single-burst model)
Response timeFirst CPU start time − Arrival time
ThroughputCompleted processes ÷ elapsed time
CPU utilizationBusy CPU time ÷ total time × 100%

Scheduling algorithms

AlgorithmTypeKey point
FCFSNon-preemptiveArrival order; can cause convoy effect.
SJFNon-preemptiveShortest CPU burst first; minimum average waiting under ideal assumptions with known bursts.
SRTFPreemptiveShortest remaining time first; preempts when a shorter remaining job arrives.
PriorityBothHighest-priority process first; low-priority starvation possible.
Round RobinPreemptiveEach process receives a time quantum; suitable for time-sharing.
Multilevel queueBothSeparate fixed queues, often with different policies.
Multilevel feedback queueBothProcesses can move between queues.
  • FCFS is simple but a long job can delay short jobs (convoy effect).
  • SJF/SRTF can starve long jobs.
  • Priority scheduling can starve low-priority jobs; aging gradually raises waiting jobs' priority.
  • Very small RR quantum causes excessive context switches; very large quantum makes RR approach FCFS.
  • RR generally improves interactive response compared with FCFS, but exact performance depends on workload and quantum.

Worked FCFS example

All arrive at time 0: P1 burst 5, P2 burst 3, P3 burst 1. Order: P1 (0–5), P2 (5–8), P3 (8–9). Waiting times: 0, 5, 8. Average waiting time = (0 + 5 + 8) / 3 = 4.33 time units.

6. Synchronization and IPC

Race condition and critical section

A race condition occurs when concurrent access to shared data makes the result depend on execution order. A critical section is the code region that accesses shared data/resources.

Correct critical-section solutions satisfy:

  1. Mutual exclusion: at most one process is in the critical section for a particular resource at a time.
  2. Progress: if the section is free and contenders exist, choosing the next entrant cannot be postponed indefinitely.
  3. Bounded waiting: a request cannot be overtaken indefinitely; there is a bound on how many entries by others occur before it.

Semaphores and mutexes

  • A semaphore is a synchronization variable operated on atomically.
  • wait/P: decrement or block when unavailable.
  • signal/V: increment and/or wake a waiter.
  • Binary semaphore: commonly takes values 0/1.
  • Counting semaphore: tracks multiple identical resource instances.
  • Mutex: ownership-based lock for mutual exclusion; normally the locking thread must unlock it.

A semaphore is not necessarily ownership-based. A counting semaphore initialized to 3 can represent three available identical resources.

Classical problems

  • Producer–Consumer (bounded buffer).
  • Readers–Writers.
  • Dining Philosophers.

Inter-process communication

IPC mechanisms include shared memory, message passing, pipes, named pipes, message queues, sockets and signals. Shared memory can be efficient for large transfers but needs synchronization. Message passing exchanges data through send/receive operations.

7. Deadlocks

Definition and four necessary conditions

Deadlock is a condition in which a set of processes remains blocked because each waits for a resource/event that another process in the set must release.

  1. Mutual exclusion: at least one resource is non-sharable.
  2. Hold and wait: a process holds resources while requesting more.
  3. No preemption: resources cannot be forcibly taken away.
  4. Circular wait: a circular chain of processes exists, each waiting for a resource held by the next.

Handling methods

MethodMeaning
PreventionEnsure at least one necessary condition cannot hold.
AvoidanceGrant requests only when the resulting state is safe.
DetectionAllow deadlocks, then detect them.
RecoveryTerminate processes or preempt resources to resolve deadlock.

Banker's Algorithm

Banker's algorithm is a deadlock-avoidance algorithm. It checks whether a resource allocation leaves a safe sequence.

  • Available: free resources.
  • Max: maximum declared demand.
  • Allocation: resources currently allocated.
  • Need = Max − Allocation.

A safe state has at least one sequence in which each process can obtain its remaining need, finish and release its resources. An unsafe state is not necessarily already deadlocked.

Resource Allocation Graph

Processes are circles; resource types are rectangles. Request edge: process → resource. Assignment edge: resource → process. With one instance of each resource type, a cycle implies deadlock; with multiple instances, a cycle alone does not necessarily prove deadlock.

Identical resource numerical shortcut

For n processes, each requiring at most k identical resources, a sufficient number to guarantee no deadlock under the standard assumptions is:

R = n(k − 1) + 1

Example: n = 3, k = 2 gives R = 3(1) + 1 = 4 resources.

8. Memory management

Address translation

  • Logical address is generated by the CPU; it is also commonly called a virtual address.
  • Physical address is the actual address in RAM.
  • MMU (Memory Management Unit) performs address translation and protection checks.

Contiguous allocation and fragmentation

  • Fixed partitions: simple, but can waste space inside partitions (internal fragmentation).
  • Variable partitions: flexible, but free holes can become scattered (external fragmentation).
  • Compaction: relocates processes to combine scattered free holes into a larger contiguous area, when relocation is supported.

Internal fragmentation is unused space inside an allocated block. External fragmentation is free space split into non-contiguous holes.

Allocation strategies

StrategyRule
First FitFirst hole large enough.
Best FitSmallest hole that is large enough.
Worst FitLargest available hole.
Next FitContinue searching from the previous allocation position.

All variable-partition strategies can leave external fragmentation. First Fit is often fast; Best Fit may leave many tiny holes. Results depend on request sequence.

Swapping

Swapping transfers a process or its memory pages between RAM and secondary storage. Swap-out moves data out; swap-in brings it back. Swap space is secondary-storage space reserved for this purpose. Modern virtual-memory systems often swap pages rather than an entire process.

9. Paging, segmentation and virtual memory

Paging

Paging divides logical memory into fixed-size pages and physical memory into equal-size frames. A page table maps page numbers to frame numbers. Page-table entries may include valid, protection, reference and dirty bits.

Logical address = page number + offset. If page size is 2d bytes, offset uses d bits. Page number bits = logical address bits − d.

Segmentation vs paging

PagingSegmentation
Fixed-size pages and frames.Variable-size logical segments.
Page table maps page to frame.Segment table stores base and limit.
Can cause internal fragmentation.Can cause external fragmentation.
Not inherently aligned with program logic.Can represent code, data and stack as logical units.

Page replacement algorithms

AlgorithmRuleBelady anomaly?
FIFOReplace the page loaded earliest.Can occur.
LRUReplace the page least recently used in the past.No.
OptimalReplace the page whose next use is farthest in the future.No.

Belady’s anomaly means that increasing the number of frames can increase page faults. FIFO can exhibit it. LRU and Optimal are stack algorithms and do not. Optimal gives the minimum page-fault count for a known reference string but requires future knowledge, so it is mainly a benchmark.

Page fault handling

  1. Hardware traps to the OS when a referenced page is absent.
  2. OS checks whether the reference is valid.
  3. OS finds the page on backing storage.
  4. Find a free frame or select a victim page.
  5. Write a dirty victim back if needed; load the required page.
  6. Update page tables/TLB and restart the faulting instruction.

Virtual memory and demand paging

Virtual memory allows a process to run without all of its address space resident in RAM. Demand paging loads pages when first referenced. It can reduce initial loading and physical-memory use.

Thrashing

Thrashing occurs when the system spends excessive time servicing page faults instead of executing processes. Causes include too few frames for active working sets and excessive multiprogramming. Working-set or page-fault-frequency control and reducing the degree of multiprogramming can help.

TLB and effective access time

Translation Lookaside Buffer (TLB) is a fast cache of recent page-table translations. For a single-level page table, with TLB lookup time tT, memory access time tM and hit ratio h:

EAT = h(tT + tM) + (1 − h)(tT + 2tM)

This assumes a TLB lookup on both paths and one memory access for the page-table entry on a miss, followed by one for the data.

10. File systems and file management

File attributes and operations

Attributes include name, identifier, type, location, size, permissions and timestamps. Common operations are create, open, read, write, append, seek, close and delete.

Seek changes the current file offset; it does not itself transfer file data.

Access methods

  • Sequential: records/data accessed in order.
  • Direct/random: access a location using an offset or block number.
  • Indexed: use an index to locate records/blocks.

Directory structures

Single-level, two-level, tree-structured, acyclic-graph and general-graph directories.

File allocation methods

MethodAdvantagesLimitations
ContiguousFast sequential and direct access.External fragmentation; file growth can be difficult.
LinkedNo need for contiguous free space; good sequential access.Poor random access; pointer overhead.
IndexedSupports direct access through index block.Index storage overhead.

FAT, inode and file-system structures

  • FAT: File Allocation Table; variants include FAT12, FAT16 and FAT32.
  • Inode: Unix-like file metadata and data-block pointers; filename is generally stored in a directory entry, not in the inode itself.
  • FCB: File Control Block, a structure holding file metadata in some file-system designs.
  • Volume control block: stores file-system/volume information such as block size and free-space details.

Linux permissions

PermissionNumeric valueMeaning
r4Read
w2Write
x1Execute

chmod 755 file means owner = 7 (rwx), group = 5 (r-x), others = 5 (r-x).

11. Disk management and scheduling

Disk terms

  • Platter: circular magnetic disk surface.
  • Track: concentric circular path.
  • Sector: subdivision of a track.
  • Cylinder: tracks at the same radius across platters.
  • Seek time: time to move head to the required track.
  • Rotational latency: waiting for desired sector to rotate under the head.
  • Transfer time: time to transfer data.

Disk access time is approximately seek time + rotational latency + transfer time (ignoring controller/queue overhead).

Disk scheduling algorithms

AlgorithmRuleImportant point
FCFSArrival orderFair order, can have large movement.
SSTFNearest pending cylinderCan starve distant requests.
SCANMoves in one direction servicing requests, then reversesElevator algorithm.
C-SCANServices in one direction, returns to start endMore uniform waiting characteristics.
LOOKLike SCAN but reverses at last pending requestAvoids travelling to physical disk end unnecessarily.
C-LOOKLike C-SCAN but jumps between last and first pending requestsCircular service among pending requests.

Total head movement = sum of absolute differences between consecutive cylinder positions.

14. Additional syllabus concepts

Booting

Typical sequence: power on → BIOS/UEFI initialization and POST → bootloader → kernel load → system initialization/services → login/interface. Cold boot starts from powered off; warm boot is a restart.

Distributed and multiprocessor systems

  • Distributed systems coordinate multiple networked computers; concepts include resource sharing, communication, replication, consistency and fault tolerance.
  • SMP (symmetric multiprocessing): processors have broadly equal roles and commonly share memory.
  • AMP (asymmetric multiprocessing): processors have different assigned roles.

Real-time scheduling

  • Rate Monotonic Scheduling (RMS): fixed priority; shorter-period periodic tasks receive higher priority.
  • Earliest Deadline First (EDF): dynamic priority; task with nearest deadline is selected.

Other useful concepts

  • Working set: pages referenced within a recent time window; helps reason about locality and thrashing.
  • Copy-on-Write: parent and child initially share pages; a page is copied when one writes to it.
  • Peterson’s algorithm: two-process software critical-section solution using flags and turn; relies on assumptions about memory ordering.
  • Priority inversion: high-priority task waits for a resource held by a lower-priority task; priority inheritance can help.
  • RAID 0: striping, no redundancy. RAID 1: mirroring. RAID 5: distributed parity. RAID 6: dual parity. RAID 10: mirrored stripes.
  • Page-table designs: single-level, multilevel, inverted and hashed page tables.

15. PYQ answer bank — direct facts to memorize

Process and scheduling

  • A program in execution is a process.
  • PCB stores process state, registers, program counter and scheduling/memory/I/O information.
  • Ready means waiting for CPU; blocked means waiting for an event or I/O.
  • fork() creates a child; exec() replaces the process image; wait() waits for a child state change.
  • Context switching saves and restores execution context.
  • Throughput = completed processes per unit time.
  • SRTF is preemptive SJF; RR uses a time quantum.
  • Priority scheduling can starve low-priority jobs; aging mitigates starvation.

Synchronization and deadlocks

  • Critical-section requirements: mutual exclusion, progress and bounded waiting.
  • Semaphore operations: atomic wait and signal.
  • Four deadlock conditions: mutual exclusion, hold-and-wait, no preemption, circular wait.
  • Banker's algorithm performs deadlock avoidance by checking safe states.
  • Unsafe state is not identical to deadlock.

Memory and paging

  • Internal fragmentation is waste inside an allocated block; external fragmentation is scattered free holes.
  • Compaction can reduce external fragmentation.
  • Swapping moves process memory between RAM and backing storage.
  • Logical memory uses pages; physical memory uses equal-sized frames.
  • Page table maps pages to frames.
  • FIFO can exhibit Belady’s anomaly; LRU and Optimal do not.
  • Optimal replaces the page whose next use is farthest in the future.
  • TLB caches address translations; page faults occur when a referenced page is absent.

Files, disks and OS fundamentals

  • FAT = File Allocation Table.
  • Seek changes file offset; seek time moves a disk head to the required track.
  • Rotational latency waits for the sector to rotate under the head.
  • SSTF selects the nearest pending disk request; FCFS follows arrival order.
  • /etc contains system configuration on Linux.
  • chmod changes permissions; grep searches text; head/tail display beginning/end lines.
  • DMA reduces CPU involvement in block transfers; spooling queues jobs such as print jobs.

Worked TLB example

If hit ratio h = 0.8, TLB lookup = 20 ns and memory access = 100 ns, then hit time = 120 ns and miss time = 220 ns under a one-level page-table assumption.

EAT = 0.8(120) + 0.2(220) = 96 + 44 = 140 ns.

Worked address-bits example

Four pages require 2 page-number bits. A page size of 2048 words requires 11 offset bits. Total logical address width = 2 + 11 = 13 bits.

Worked FIFO page replacement example

Reference string: 1, 2, 3, 1, 4; three initially empty frames. FIFO sequence: 1 (fault), 2 (fault), 3 (fault), 1 (hit), 4 (fault; replace 1). Total = 4 page faults.
