2. Operating System fundamentals

Definition and objectives

An Operating System is system software that acts as an interface between users/applications and computer hardware. It manages resources and provides services to programs.

  • Convenience: makes the computer easier to use.
  • Efficiency: uses CPU, memory and devices effectively.
  • Resource management: allocates and releases resources.
  • Protection: isolates processes and controls access.
  • Abstraction: hides low-level hardware details.

Main functions

FunctionResponsibility
Process managementCreate, schedule, synchronize and terminate processes.
Memory managementTrack, allocate, protect and reclaim memory.
File managementCreate, organize, read, write and delete files.
Device managementControl devices through drivers and I/O subsystems.
SecurityAuthentication, permissions and protection.
User interfaceProvide CLI or GUI.

Types of operating systems

  • Batch OS: executes grouped jobs with little/no interaction during execution.
  • Multiprogramming: keeps multiple jobs in memory; CPU can run another job when one waits for I/O.
  • Time-sharing: allocates CPU time slices for interactive use.
  • Multitasking: supports multiple tasks through scheduling and context switching.
  • Multiprocessing: uses multiple processors or cores.
  • Multi-user: supports concurrent users.
  • Distributed OS: coordinates resources across multiple computers.
  • Network OS: provides network services such as shared files and printers.
  • Real-time OS: designed to meet timing constraints; hard real-time deadlines are critical, soft real-time misses may be tolerable.
  • Embedded OS: designed for dedicated devices.

Important comparisons

ConceptsDifference
Multiprogramming vs multitaskingMultiprogramming emphasizes CPU utilization; multitasking emphasizes responsive concurrent task execution.
Multiprocessing vs multitaskingMultiprocessing uses multiple processing units; multitasking can time-share one CPU.
Hard vs soft real-timeHard deadlines must not be missed; soft deadlines are desirable but occasional misses may be tolerated.

Kernel, shell and drivers

  • Kernel: privileged core of the operating system.
  • Shell: command interpreter/interface.
  • Device driver: software that controls a hardware device.
  • System utility: maintenance and management program.
Exam focus: MEDIUM PRIORITY — Learn system-call categories, Unix calls and OS architecture. Repeated PYQ themes include sleep/wait-for-time and communication system calls.

Deeper concepts: OS fundamentals

Operating system = resource manager + control program + user interface. It allocates CPU time, main memory, storage and I/O devices; controls program execution; enforces protection; and offers common services through system calls and APIs.

  • Convenience: hides hardware complexity and provides a consistent environment. Efficiency: shares hardware while trying to keep CPU and devices busy. Evolution: supports new hardware and services without requiring every application to manage devices directly.
  • Batch: jobs are collected and run with little or no interaction. Multiprogramming: several jobs stay in memory so the CPU can switch when one waits for I/O. Time-sharing: preemptive time slices give interactive users responsive service. Real-time: correctness includes meeting timing deadlines.
  • Multiprocessing means multiple CPUs/cores execute work; multitasking means multiple tasks make progress; multithreading means multiple execution paths exist within a process; multi-user means multiple users can use the system, often concurrently.
  • Kernel: privileged core that handles scheduling, memory, interrupts and device access. Shell: command interpreter/user interface. Device driver: OS component that translates generic I/O requests into device-specific operations. GUI means Graphical User Interface.

Exam traps: Android is an operating system; Edge, Firefox and Word are applications. An OS does not itself guarantee that every application is secure or bug-free. Multiprogramming and multiprocessing are not synonyms.

3. OS structure and system calls

Kernel architectures

  • Monolithic: most OS services execute in kernel space. Linux is a modular monolithic kernel.
  • Microkernel: keeps only essential mechanisms in kernel; more services run in user space. MINIX 3 is a common example.
  • Hybrid: combines design approaches; Windows NT is commonly described as hybrid.
  • Modular: supports separately loadable kernel modules.

System calls

A system call is the controlled interface through which a user program requests a kernel service.

CategoryExamples
Process controlfork(), exec(), wait(), exit()
File managementopen(), read(), write(), close(), lseek()
Device managementDevice request/release and device operations
Information maintenancegetpid(), time(), system information
Communicationpipe(), socket(), send(), receive()

Important Unix calls

  • fork() creates a child process.
  • exec() family replaces the current process image with a new program.
  • wait() waits for a child process state change/termination.
  • exit() terminates a process.
  • open(), read(), write(), close() manage file descriptors.
  • lseek() changes the file offset; it does not itself read or write file data.
  • sleep() suspends execution for a specified duration.

fork() return: negative = failure; zero = child; positive = parent receives child PID.

User mode vs kernel mode

User modeKernel mode
Restricted privileges; applications commonly execute here.Privileged execution; kernel controls protected resources.
Requests services through system calls.Can execute privileged instructions.

A mode switch does not necessarily imply a process/context switch.

Exam focus: VERY HIGH PRIORITY — Process states, PCB, process vs thread, context switching, queues and swapping. Repeated PYQ: identify a non-process state (3 occurrences).

Deeper concepts: OS architecture and system calls

A user program normally requests privileged services through a system-call interface. A library/API wrapper places arguments in the required registers, stack or memory, executes a trap/syscall instruction, and transfers control to the kernel. The kernel validates arguments and permissions, performs the operation, then returns a result or error.

System-call categoryTypical workExamples
Process controlCreate, execute, wait for, terminate processesfork, exec, wait, exit
File managementCreate/open/read/write/close/seek filesopen, read, write, lseek, close
Device managementRequest/release devices; read/write device dataioctl, device read/write
Information maintenanceRead or set process/system attributesgetpid, time, uname
CommunicationExchange data between processespipe, socket, send, receive
ProtectionControl access rights and identitychmod, setuid, access checks

fork() creates a child process; on success it returns 0 in the child and the child's PID in the parent, while a negative value indicates failure. exec() replaces the current process image with a new program. wait() collects a child's termination status. write() returns the number of bytes written (or -1 on error); in POSIX its return type is ssize_t.

Monolithic kernel: many OS services execute in kernel space, often improving direct-call performance but increasing the trusted code base. Microkernel: keeps a small core in kernel mode and moves more services to user space; modularity and fault isolation improve, but message-passing overhead may increase. A user-to-kernel transition is not the same as a process context switch.

4. Process management and threads

Process vs program

A process is a program in execution. A program is passive code; a process is an executing entity with state and allocated resources.

Process Control Block (PCB)

The OS maintains a PCB for each process. It commonly stores:

  • Process ID and process state.
  • Program counter and CPU registers.
  • CPU scheduling information.
  • Memory-management information.
  • I/O status and open-resource information.
  • Accounting and ownership information.

Five-state process model

StateMeaning
NewBeing created.
ReadyWaiting for CPU.
RunningCurrently executing on CPU.
Waiting/BlockedWaiting for I/O or an event.
TerminatedExecution has ended.
  • New → Ready: admitted.
  • Ready → Running: dispatch.
  • Running → Ready: preemption/time slice expires.
  • Running → Waiting: requests I/O or waits for event.
  • Waiting → Ready: event/I/O completes.
  • Running → Terminated: exit.

Job queue contains submitted jobs; ready queue contains processes waiting for CPU; device queues contain processes waiting for devices.

Context switching

Context switching saves the current execution state and restores another process/thread's state. It involves saving registers/program counter, selecting the next runnable entity and restoring its context. It is overhead: the CPU does not perform useful work for the switched user processes during the switch itself.

Process vs thread

ProcessThread
Has its own address space and process resources.Execution path within a process; shares process address space/resources.
Separate processes usually communicate through IPC.Threads communicate through shared process memory.
Creation/context management is generally heavier.Usually lighter-weight.

Threads in one process share code, data, heap and many process resources. Each thread has its own stack, registers, program counter and thread ID. User-level threads are managed by a user-space library; kernel-level threads are managed by the OS.

Schedulers

  • Long-term scheduler: admits jobs into the system/memory.
  • Short-term scheduler: selects the next process for CPU.
  • Medium-term scheduler: suspends/swaps processes out and later brings them back.
  • Dispatcher: transfers CPU control to the selected process.

A zombie is a terminated process whose exit status has not yet been collected by its parent. A process waiting for I/O is normally blocked, not ready.

Exam focus: VERY HIGH PRIORITY — FCFS, SJF/SRTF, Priority and Round Robin; Gantt charts; waiting, turnaround, response time and throughput. Repeated PYQ: identify a non-CPU scheduling algorithm (2 occurrences).

Deeper concepts: processes and threads

A program is passive code stored on disk; a process is an executing instance with its own virtual address space and resources. A process can contain one or more threads. Threads in the same process share code, data, heap and open files, but each thread has its own program counter, registers and stack.

StateMeaningTypical transition
NewBeing createdAdmitted → Ready
ReadyCan run, waiting for CPUDispatcher → Running
RunningCurrently executingPreempted → Ready; I/O wait → Blocked
Blocked/WaitingWaiting for an event or I/OEvent completes → Ready
TerminatedExecution finishedResources reclaimed

A PCB stores process ID/state, program counter, CPU registers, scheduling data, memory-management information, accounting data and I/O/open-file status. The OS saves and restores this context during a process switch. A TCB stores per-thread state. A zombie has terminated but still has a process-table entry awaiting parent collection; an orphan is a child whose parent has terminated.

Context switch cost: saving/restoring registers and changing address-space or scheduling state consumes time but performs no useful application work. A thread switch within one process can be cheaper than switching between processes, although kernel scheduling and memory effects still matter. The long-term scheduler admits jobs, the short-term scheduler chooses the next ready task, and the medium-term scheduler can swap processes out/in.

Exam trap: a blocked process normally becomes ready—not running—when its event completes. “Privileged” is not a standard process state in the five-state model.

5. CPU scheduling

Objectives and formulas

  • Maximize CPU utilization and throughput.
  • Minimize turnaround, waiting and response time.
  • Provide fairness and avoid starvation.
MeasureFormula
Turnaround time (TAT)Completion time − Arrival time
Waiting time (WT)TAT − CPU burst time (for the standard single-burst model)
Response timeFirst CPU start time − Arrival time
ThroughputCompleted processes ÷ elapsed time
CPU utilizationBusy CPU time ÷ total time × 100%

Scheduling algorithms

AlgorithmTypeKey point
FCFSNon-preemptiveArrival order; can cause convoy effect.
SJFNon-preemptiveShortest CPU burst first; minimum average waiting under ideal assumptions with known bursts.
SRTFPreemptiveShortest remaining time first; preempts when a shorter remaining job arrives.
PriorityBothHighest-priority process first; low-priority starvation possible.
Round RobinPreemptiveEach process receives a time quantum; suitable for time-sharing.
Multilevel queueBothSeparate fixed queues, often with different policies.
Multilevel feedback queueBothProcesses can move between queues.
  • FCFS is simple but a long job can delay short jobs (convoy effect).
  • SJF/SRTF can starve long jobs.
  • Priority scheduling can starve low-priority jobs; aging gradually raises waiting jobs' priority.
  • Very small RR quantum causes excessive context switches; very large quantum makes RR approach FCFS.
  • RR generally improves interactive response compared with FCFS, but exact performance depends on workload and quantum.

Worked FCFS example

All arrive at time 0: P1 burst 5, P2 burst 3, P3 burst 1. Order: P1 (0–5), P2 (5–8), P3 (8–9). Waiting times: 0, 5, 8. Average waiting time = (0 + 5 + 8) / 3 = 4.33 time units.

Exam focus: HIGH PRIORITY — Critical-section requirements, semaphores, wait/signal, bounded waiting and race conditions.

Deeper concepts: CPU scheduling

Scheduling chooses a ready process/thread for the CPU. Preemptive scheduling can interrupt a running task; non-preemptive scheduling lets it continue until it blocks or finishes. Compare algorithms using the same arrival and burst-time data—do not confuse CPU scheduling with disk-head scheduling.

AlgorithmSelection ruleStrength / risk
FCFSEarliest arrival firstSimple and non-preemptive; convoy effect can increase average waiting time.
SJFSmallest next CPU burstMinimum average waiting time when burst lengths are known; long jobs may starve.
SRTFSmallest remaining burstPreemptive SJF; can starve long jobs.
PriorityHighest priority firstLow-priority starvation; aging gradually raises waiting tasks' priority.
Round RobinEach ready task gets a time quantumResponsive and fair; tiny quantum causes excessive context switching.
Multilevel feedback queueTasks move between priority queuesAdapts to behaviour; policy is more complex.

Core formulas: Turnaround time = Completion − Arrival. Waiting time = Turnaround − CPU burst time (for a single CPU burst). Response time = First CPU start − Arrival. Throughput = Completed processes / unit time. CPU utilization = Busy time / total time × 100%.

Round Robin efficiency approximation: if context-switch time is s and useful CPU burst between switches is q, useful fraction ≈ q/(q+s). Example: q=6, s=4 gives 6/10 = 60%. This assumes one switch overhead per useful quantum and ignores other overheads.

Numerical method: draw a Gantt chart; calculate each completion time; then calculate turnaround and waiting time per process; average only after each value is found. For Round Robin, maintain the ready queue in arrival order and reinsert unfinished jobs at the tail. For SRTF, reconsider the shortest remaining time whenever a process arrives.

PYQ questions and answers

  1. [2024] Which CPU scheduling algorithm can cause starvation of low-priority processes unless aging is used?
    Answer: Priority Scheduling.
  2. [2021] Which is not a CPU scheduling algorithm: FCFS, Round Robin, Priority, or C-SCAN?
    Answer: C-SCAN. It is a disk-scheduling algorithm.
  3. [2020] Which scheduling algorithm gives maximum throughput when task run times are known, under the usual single-CPU assumptions?
    Answer: Shortest Job First (SJF).
  4. [2016] What is the system load when 10 processes arrive per minute and average service time is 3 seconds?
    Answer: 0.5 (arrival rate × average service time).
  5. [2020] With 4 units of context-switch time and 6 units of useful running time before blocking, what is the CPU efficiency under the simplified model?
    Answer: 6 / (6 + 4) = 0.6, or 60%.

6. Synchronization and IPC

Race condition and critical section

A race condition occurs when concurrent access to shared data makes the result depend on execution order. A critical section is the code region that accesses shared data/resources.

Correct critical-section solutions satisfy:

  1. Mutual exclusion: at most one process is in the critical section for a particular resource at a time.
  2. Progress: if the section is free and contenders exist, choosing the next entrant cannot be postponed indefinitely.
  3. Bounded waiting: a request cannot be overtaken indefinitely; there is a bound on how many entries by others occur before it.

Semaphores and mutexes

  • A semaphore is a synchronization variable operated on atomically.
  • wait/P: decrement or block when unavailable.
  • signal/V: increment and/or wake a waiter.
  • Binary semaphore: commonly takes values 0/1.
  • Counting semaphore: tracks multiple identical resource instances.
  • Mutex: ownership-based lock for mutual exclusion; normally the locking thread must unlock it.

A semaphore is not necessarily ownership-based. A counting semaphore initialized to 3 can represent three available identical resources.

Classical problems

  • Producer–Consumer (bounded buffer).
  • Readers–Writers.
  • Dining Philosophers.

Inter-process communication

IPC mechanisms include shared memory, message passing, pipes, named pipes, message queues, sockets and signals. Shared memory can be efficient for large transfers but needs synchronization. Message passing exchanges data through send/receive operations.

Exam focus: HIGH PRIORITY — Four necessary conditions, prevention vs avoidance, safe/unsafe states and Banker’s algorithm. Practice resource-allocation numericals.

Deeper concepts: synchronization and IPC

A race condition occurs when the result depends on the timing/interleaving of concurrent operations. A critical section accesses shared state. A correct solution must satisfy mutual exclusion (at most one process inside), progress (selection cannot be postponed indefinitely when the section is free), and bounded waiting (a finite bound exists on overtaking).

A semaphore is an integer synchronization variable accessed through atomic operations. wait(P) decrements/claims a resource and may block; signal(V) increments/releases and may wake a waiter. A binary semaphore can enforce mutual exclusion; a counting semaphore represents multiple identical resources. A mutex additionally has ownership semantics in common implementations.

Classical problems: producer-consumer uses empty/full counting semaphores plus a mutex; readers-writers coordinates shared reads and exclusive writes; dining philosophers illustrates deadlock and starvation risks. Busy waiting repeatedly checks a condition; blocking synchronization sleeps until awakened.

IPC models: shared memory is fast after setup but requires explicit synchronization. Message passing uses send/receive and can be direct or mailbox-based; pipes/FIFOs, message queues, sockets and signals are common mechanisms. A socket endpoint is typically identified by an address plus port/protocol. Distributed consistency can use replication protocols, ordering, consensus or coordination; the correct mechanism depends on consistency guarantees.

Exam trap: bounded waiting is a property of a correct critical-section solution; it is not guaranteed merely by using a generic lock if its scheduling policy is unfair.

PYQ questions and answers

  1. [2025] Which conditions must be satisfied by a correct critical-section solution?
    Answer: Mutual exclusion, progress and bounded waiting.
  2. [2024] Which standard atomic operations are used with a semaphore?
    Answer: wait() and signal().
  3. [2022] What is the key property of semaphore wait() and signal() operations?

7. Deadlocks

Definition and four necessary conditions

Deadlock is a condition in which a set of processes remains blocked because each waits for a resource/event that another process in the set must release.

  1. Mutual exclusion: at least one resource is non-sharable.
  2. Hold and wait: a process holds resources while requesting more.
  3. No preemption: resources cannot be forcibly taken away.
  4. Circular wait: a circular chain of processes exists, each waiting for a resource held by the next.

Handling methods

MethodMeaning
PreventionEnsure at least one necessary condition cannot hold.
AvoidanceGrant requests only when the resulting state is safe.
DetectionAllow deadlocks, then detect them.
RecoveryTerminate processes or preempt resources to resolve deadlock.

Banker's Algorithm

Banker's algorithm is a deadlock-avoidance algorithm. It checks whether a resource allocation leaves a safe sequence.

  • Available: free resources.
  • Max: maximum declared demand.
  • Allocation: resources currently allocated.
  • Need = Max − Allocation.

A safe state has at least one sequence in which each process can obtain its remaining need, finish and release its resources. An unsafe state is not necessarily already deadlocked.

Resource Allocation Graph

Processes are circles; resource types are rectangles. Request edge: process → resource. Assignment edge: resource → process. With one instance of each resource type, a cycle implies deadlock; with multiple instances, a cycle alone does not necessarily prove deadlock.

Identical resource numerical shortcut

For n processes, each requiring at most k identical resources, a sufficient number to guarantee no deadlock under the standard assumptions is:

R = n(k − 1) + 1

Example: n = 3, k = 2 gives R = 3(1) + 1 = 4 resources.

Exam focus: VERY HIGH PRIORITY — Internal/external fragmentation, First-Fit/Best-Fit, swapping, logical vs physical addresses and memory protection.

Deeper concepts: deadlocks

Deadlock is a set of processes permanently waiting for resources/events that only members of the set can cause. The four Coffman conditions must all hold: mutual exclusion, hold and wait, no preemption, and circular wait. Breaking any one condition prevents deadlock.

ApproachIdeaTrade-off
PreventionDesign policy so at least one Coffman condition cannot holdCan reduce utilization or flexibility.
AvoidanceGrant a request only if the resulting state is safeNeeds advance maximum-demand information.
Detection and recoveryAllow deadlock, detect it, then recoverDetection/recovery costs; may abort or preempt.
IgnoreAssume deadlocks are sufficiently rareMay be acceptable in some general-purpose systems, not universally safe.

Safe state: there exists an ordering in which every process can obtain its remaining maximum need, finish and release resources. Banker’s algorithm tests this before granting a request. An unsafe state is not necessarily already deadlocked; it means no guaranteed safe sequence is known.

Single resource type shortcut: if n processes may each need at most k identical units, then R ≥ n(k−1)+1 units guarantees that at least one process can obtain its full requirement and finish. This assumes each process holds at most k−1 while waiting for its final unit. For 7 units and k=2, at most 6 such processes can be guaranteed safe.

Resource-allocation graph: process→resource is a request edge; resource→process is an assignment edge. With one instance per resource type, a cycle implies deadlock; with multiple instances, a cycle is necessary but not sufficient.

  1. [2023] Banker's algorithm is an example of which deadlock-handling method?
    Answer: Deadlock avoidance.
  2. [2017] Three processes each require at most two units of an identical resource. What minimum number guarantees no deadlock under the standard assumptions?
    Answer: 4, using R = n(k − 1) + 1.
  3. [2018] Which is not one of the four necessary deadlock conditions: mutual exclusion, hold-and-wait, no preemption, or preemption?
    Answer: Preemption. The necessary condition is no preemption.
  4. [2021] Seven tape drives are shared by processes, each of which may need two drives. What is the maximum number of processes guaranteed deadlock-free?

8. Memory management

Address translation

  • Logical address is generated by the CPU; it is also commonly called a virtual address.
  • Physical address is the actual address in RAM.
  • MMU (Memory Management Unit) performs address translation and protection checks.

Contiguous allocation and fragmentation

  • Fixed partitions: simple, but can waste space inside partitions (internal fragmentation).
  • Variable partitions: flexible, but free holes can become scattered (external fragmentation).
  • Compaction: relocates processes to combine scattered free holes into a larger contiguous area, when relocation is supported.

Internal fragmentation is unused space inside an allocated block. External fragmentation is free space split into non-contiguous holes.

Allocation strategies

StrategyRule
First FitFirst hole large enough.
Best FitSmallest hole that is large enough.
Worst FitLargest available hole.
Next FitContinue searching from the previous allocation position.

All variable-partition strategies can leave external fragmentation. First Fit is often fast; Best Fit may leave many tiny holes. Results depend on request sequence.

Swapping

Swapping transfers a process or its memory pages between RAM and secondary storage. Swap-out moves data out; swap-in brings it back. Swap space is secondary-storage space reserved for this purpose. Modern virtual-memory systems often swap pages rather than an entire process.

Exam focus: VERY HIGH PRIORITY — Page/frame mapping, page faults, FIFO/LRU/Optimal, Belady’s anomaly, TLB and address-bit numericals. Belady’s anomaly/page replacement is a repeated PYQ theme.

Deeper concepts: memory management

The MMU translates a process's logical/virtual address to a physical address. Address binding may occur at compile time, load time or execution time. Relocation and protection registers (base/limit or equivalent bounds) restrict a process to its permitted memory region.

Contiguous allocation: a process occupies one continuous memory region. Fixed partitions are simple but waste space inside allocated partitions (internal fragmentation). Variable partitions can leave separated free holes (external fragmentation); compaction can combine holes but requires relocation and time.

StrategyRuleTypical effect
First fitFirst adequate holeFast; may leave small holes near the beginning.
Best fitSmallest adequate holeMay create many tiny unusable holes; search can be expensive.
Worst fitLargest available holeLeaves a larger remainder; not generally optimal.
Next fitContinue search from previous positionReduces repeated scanning from the start.

Internal fragmentation is wasted space inside an allocated block; external fragmentation is free space split into non-contiguous holes. If a process of size c cannot fit in either hole a or b although a+b>c, the issue is external fragmentation.

Swapping out moves a process from RAM to backing store; swapping in brings it back. Swap space is disk/SSD space reserved for this purpose. Swapping is distinct from paging: paging moves fixed-size pages, often on demand, whereas classical swapping moves a process or large process image.

  1. [2013] First-Fit and Best-Fit variable-partition allocation can suffer from which type of fragmentation?

    Answer: Memory protection; it establishes a boundary that a process must not cross.
  3. [2021] A process cannot fit in either of two separate free holes even though their combined size is sufficient. What is this problem called?
    Answer: External fragmentation.

9. Paging, segmentation and virtual memory

Paging

Paging divides logical memory into fixed-size pages and physical memory into equal-size frames. A page table maps page numbers to frame numbers. Page-table entries may include valid, protection, reference and dirty bits.

Logical address = page number + offset. If page size is 2d bytes, offset uses d bits. Page number bits = logical address bits − d.

Segmentation vs paging

PagingSegmentation

Page replacement algorithms

AlgorithmRuleBelady anomaly?
FIFOReplace the page loaded earliest.Can occur.
LRUReplace the page least recently used in the past.No.
OptimalReplace the page whose next use is farthest in the future.No.

Belady’s anomaly means that increasing the number of frames can increase page faults. FIFO can exhibit it. LRU and Optimal are stack algorithms and do not. Optimal gives the minimum page-fault count for a known reference string but requires future knowledge, so it is mainly a benchmark.

Page fault handling

  1. Hardware traps to the OS when a referenced page is absent.
  2. OS checks whether the reference is valid.
  3. OS finds the page on backing storage.
  4. Find a free frame or select a victim page.
  5. Write a dirty victim back if needed; load the required page.
  6. Update page tables/TLB and restart the faulting instruction.

Virtual memory and demand paging

Virtual memory allows a process to run without all of its address space resident in RAM. Demand paging loads pages when first referenced. It can reduce initial loading and physical-memory use.

Thrashing

Thrashing occurs when the system spends excessive time servicing page faults instead of executing processes. Causes include too few frames for active working sets and excessive multiprogramming. Working-set or page-fault-frequency control and reducing the degree of multiprogramming can help.

TLB and effective access time

Translation Lookaside Buffer (TLB) is a fast cache of recent page-table translations. For a single-level page table, with TLB lookup time tT, memory access time tM and hit ratio h:

EAT = h(tT + tM) + (1 − h)(tT + 2tM)

This assumes a TLB lookup on both paths and one memory access for the page-table entry on a miss, followed by one for the data.

Exam focus: HIGH PRIORITY — File allocation, FAT, directories, file operations and file seek. Repeated PYQ: repositioning the file pointer without transferring file data.

Deeper concepts: paging, virtual memory and TLB

Paging divides virtual memory into fixed-size pages and physical memory into equal-size frames. A page table maps virtual page numbers to frame numbers and stores status/protection bits. A logical address is split into page number and offset; with page size 2p, the offset uses p bits. If there are 2v virtual pages, the page number uses v bits and the logical address uses v+p bits.

Page fault: the referenced page is not currently resident or the access is invalid. The OS validates the reference, obtains a free frame or chooses a victim, writes a dirty victim if needed, reads the required page, updates tables/TLB and restarts the instruction. Invalid references cause a protection fault rather than a successful page-in.

ReplacementRuleExam property
FIFOEvict oldest loaded pageCan exhibit Belady’s anomaly.
LRUEvict page unused for the longest past intervalStack algorithm; does not exhibit Belady’s anomaly.
OptimalEvict page whose next use is farthest in the futureTheoretical lower bound; future references are not known in practice.
Clock/Second chanceFIFO-like scan using reference bitPractical LRU approximation.

Belady’s anomaly means increasing the number of frames can increase FIFO page faults. LRU and Optimal are stack algorithms and do not have this anomaly. Thrashing occurs when the system spends excessive time paging rather than executing; working-set and page-fault-frequency controls help limit it.

TLB: a small associative cache of page-table translations. If a hit takes th and a miss takes tm, simple EAT = h·th + (1−h)·tm, provided the supplied hit/miss times already include all required memory accesses. If a question gives TLB lookup and memory-access components separately, count the correct accesses on both hit and miss before averaging.

Segmentation divides a program into logical variable-sized units (code, data, stack); paging divides memory into fixed-size blocks. Segmentation matches logical program structure but can suffer external fragmentation; paging avoids external fragmentation in physical frame allocation but can have internal waste in the last page.

10. File systems and file management

File attributes and operations

Attributes include name, identifier, type, location, size, permissions and timestamps. Common operations are create, open, read, write, append, seek, close and delete.

Seek changes the current file offset; it does not itself transfer file data.

Access methods

  • Sequential: records/data accessed in order.
  • Direct/random: access a location using an offset or block number.
  • Indexed: use an index to locate records/blocks.

Directory structures

Single-level, two-level, tree-structured, acyclic-graph and general-graph directories.

Deeper concepts: files and file systems

A file is a named collection of information. Common metadata include name, identifier, type, location, size, owner, permissions and timestamps. Core operations include create, open, read, write, append, reposition/seek, close, rename and delete. A seek changes the current file offset; it may update metadata/state without transferring file contents.

11. Disk management and scheduling

Disk terms

  • Platter: circular magnetic disk surface.
  • Track: concentric circular path.
  • Sector: subdivision of a track.
  • Cylinder: tracks at the same radius across platters.
  • Seek time: time to move head to the required track.
  • Rotational latency: waiting for desired sector to rotate under the head.
  • Transfer time: time to transfer data.

Disk access time is approximately seek time + rotational latency + transfer time (ignoring controller/queue overhead).

Disk scheduling algorithms

AlgorithmRuleImportant point
FCFSArrival orderFair order, can have large movement.
SSTFNearest pending cylinderCan starve distant requests.
SCANMoves in one direction servicing requests, then reversesElevator algorithm.
C-SCANServices in one direction, returns to start endMore uniform waiting characteristics.
LOOKLike SCAN but reverses at last pending requestAvoids travelling to physical disk end unnecessarily.
C-LOOKLike C-SCAN but jumps between last and first pending requestsCircular service among pending requests.

Total head movement = sum of absolute differences between consecutive cylinder positions.

Deeper concepts: disk organization and scheduling

Magnetic disks are organized into platters/surfaces, tracks, sectors and cylinders. A cylinder contains tracks at the same radius across surfaces. Disk access time is approximately seek time + rotational latency + transfer time + controller overhead. Seek time moves the head to the required track; rotational latency waits for the sector to rotate under the head.

AlgorithmHead movement policyKey point
FCFSServe in arrival orderFair/simple, but can cause large movement.
SSTFNearest request firstReduces average seek in many cases; far requests may starve.
SCANMove in one direction servicing requests, then reverseElevator algorithm.
C-SCANService in one direction; return to start without servicing on returnMore uniform wait distribution.
LOOK/C-LOOKLike SCAN/C-SCAN but reverse/jump at last pending requestAvoids travelling to physical disk ends unnecessarily.

Numerical method: write the initial head position, sort pending requests into lower/higher groups, follow the exact direction and algorithm rule, then sum absolute differences between consecutive positions. For circular algorithms include the wrap-around movement when the question counts it; state clearly whether the return jump is counted.

RAID: mirroring (commonly RAID 1) duplicates data and offers redundancy but uses roughly double the raw capacity for two-way mirrors. Striping improves parallel throughput but alone provides no redundancy. Parity-based levels trade write overhead for better capacity efficiency and fault tolerance.

  3. [2021] Name the main physical organization terms of a disk.

TechniqueHow it works

DMADirect Memory Access transfers blocks between device and memory with limited CPU involvement.
  • Buffering: temporarily stores data to accommodate speed/size differences between producers and consumers.
  • Spooling: queues complete jobs for a shared device, e.g. printer queue.
  • Driver: software interface for controlling a hardware device.

Deeper concepts: device and I/O management

The OS provides a uniform interface to heterogeneous devices through device drivers. An I/O request may pass through the application, system-call layer, device-independent I/O software, driver and controller. Device queues hold requests waiting for a device or service.

  • Programmed I/O/polling: CPU repeatedly checks device status and transfers data; simple but wastes CPU cycles.
  • Interrupt-driven I/O: device/controller interrupts the CPU when service or data is ready; CPU can do other work between events.
  • DMA: a DMA controller transfers blocks between device and memory with limited CPU involvement; CPU is typically interrupted on completion.
  • Buffering: temporary memory smooths speed/size differences between producer and consumer. Double buffering can overlap computation and I/O.
  • Caching: keeps copies of frequently used data for faster future access. Spooling: queues jobs for a device that serves one job at a time, such as a printer.

Printer types: impact printers physically strike an ink ribbon/paper (e.g. dot-matrix); laser and inkjet are non-impact. A blocked process waiting for I/O becomes ready when the I/O completion event occurs, then waits for CPU scheduling.

Exam trap: buffering, caching and spooling solve different problems. A buffer handles rate mismatch/temporary transfer; a cache exploits reuse; spooling queues complete jobs for a shared device.

14. Additional syllabus concepts

Booting

Typical sequence: power on → BIOS/UEFI initialization and POST → bootloader → kernel load → system initialization/services → login/interface. Cold boot starts from powered off; warm boot is a restart.

Distributed and multiprocessor systems

  • Distributed systems coordinate multiple networked computers; concepts include resource sharing, communication, replication, consistency and fault tolerance.
  • SMP (symmetric multiprocessing): processors have broadly equal roles and commonly share memory.
  • AMP (asymmetric multiprocessing): processors have different assigned roles.

Real-time scheduling

  • Rate Monotonic Scheduling (RMS): fixed priority; shorter-period periodic tasks receive higher priority.
  • Earliest Deadline First (EDF): dynamic priority; task with nearest deadline is selected.

Other useful concepts

  • Working set: pages referenced within a recent time window; helps reason about locality and thrashing.
  • Copy-on-Write: parent and child initially share pages; a page is copied when one writes to it.
  • Peterson’s algorithm: two-process software critical-section solution using flags and turn; relies on assumptions about memory ordering.
  • Priority inversion: high-priority task waits for a resource held by a lower-priority task; priority inheritance can help.
  • RAID 0: striping, no redundancy. RAID 1: mirroring. RAID 5: distributed parity. RAID 6: dual parity. RAID 10: mirrored stripes.
  • Page-table designs: single-level, multilevel, inverted and hashed page tables.

Deeper concepts: additional OS syllabus areas

  • Booting: firmware (BIOS/UEFI) initializes hardware and selects a boot device; a bootloader loads the kernel; the kernel initializes memory, drivers and core services, then starts the first user-space service/process.
  • Distributed OS/system: multiple networked computers coordinate and share resources. Transparency, communication, naming, synchronization, replication and fault tolerance are major design concerns. Replication improves availability/performance but creates consistency challenges.
  • Multiprocessor systems: processors share memory/I/O in a tightly coupled system. Symmetric multiprocessing allows processors to run OS tasks; cache coherence and synchronization are important.
  • Real-time systems: hard real-time systems must meet deadlines; missing one can be catastrophic. Soft real-time systems degrade in quality when deadlines are missed. Rate-monotonic scheduling assigns shorter periods higher fixed priority; earliest-deadline-first chooses the closest absolute deadline.
  • Virtualization: a hypervisor creates and manages virtual machines. Type 1 runs directly on hardware; Type 2 runs above a host OS. Containers isolate processes while sharing the host kernel.
  • Copy-on-write: parent and child initially share physical pages after process creation; a page is copied only when one attempts to modify it. This reduces unnecessary copying.
  • Working set: pages referenced in a recent time window; keeping the working set resident helps reduce thrashing. Locality of reference explains why recently/nearby used pages are likely to be reused.

Revision rule: distinguish a concept's definition, purpose, mechanism, advantage, limitation and one common example. This structure helps answer both direct-definition and “which statement is incorrect?” MCQs.

Worked TLB example

If hit ratio h = 0.8, TLB lookup = 20 ns and memory access = 100 ns, then hit time = 120 ns and miss time = 220 ns under a one-level page-table assumption.

EAT = 0.8(120) + 0.2(220) = 96 + 44 = 140 ns.

Worked address-bits example

Four pages require 2 page-number bits. A page size of 2048 words requires 11 offset bits. Total logical address width = 2 + 11 = 13 bits.

Worked FIFO page replacement example

Reference string: 1, 2, 3, 1, 4; three initially empty frames. FIFO sequence: 1 (fault), 2 (fault), 3 (fault), 1 (hit), 4 (fault; replace 1). Total = 4 page faults.
