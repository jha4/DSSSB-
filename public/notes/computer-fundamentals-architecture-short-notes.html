1. Computer generations and history

A computer generation is a broad historical classification based on the dominant electronic technology used to build computers. Generation boundaries are approximate; textbooks may differ in dates and in the description of the fifth generation.

GenerationMain technologyTypical characteristics / exam cue
FirstVacuum tubesVery large, expensive, high heat and power consumption; machine-language programming; punched cards and magnetic drums/tapes.
SecondTransistorsSmaller, faster, more reliable and lower power than vacuum-tube systems; assembly language and early high-level languages.
ThirdIntegrated circuits (ICs)Multiple electronic components integrated on chips; improved reliability, size, speed and cost.
FourthMicroprocessors; VLSICPU placed on a microprocessor chip; personal computers and widespread computerisation.
FifthOften associated with AI, knowledge processing and advanced parallel processingNot a universally fixed technical boundary; follow the wording used in the question.

ENIAC (Electronic Numerical Integrator and Computer) was an early large-scale, general-purpose electronic digital computer. Be precise with “first computer”: the answer changes depending on whether the question means first mechanical, electronic, programmable, stored-program or commercially available computer.

Exam distinction: transistor = second generation; integrated circuit = third; microprocessor = fourth; vacuum tube = first.

Input devices convert user actions or external information into signals/data that a computer can process. Examples include keyboard, mouse, scanner, microphone, webcam, barcode reader, OCR/OMR readers, biometric sensors and joystick.

Output devices present processed information in a human-usable form: monitor/display, printer, plotter, speakers and projector. A touchscreen is both input (touch sensing) and output (display).

3. Memory organisation, hierarchy and storage

Computer memory stores instructions, data and intermediate/final results. The memory hierarchy balances speed, capacity and cost: the closer storage is to the CPU, the faster and smaller it tends to be.

LevelPurposeKey properties
CPU registersHold current operands, addresses, instructions and statusSmallest and fastest storage directly inside the processor.
Cache (L1/L2/L3)Keeps copies of frequently/recently used instructions and data close to CPUVery fast; reduces average memory access time. Usually SRAM.
Main memory (RAM)Working space for active programs and dataUsually volatile; DRAM is commonly used as main memory.
ROM / non-volatile memoryStores firmware or persistent dataRetains contents without power. ROM family includes PROM, EPROM and EEPROM/flash.
Secondary storageLong-term storage of programs and filesSSD, HDD, optical discs and magnetic tape; larger capacity and slower than main memory.

Volatile memory loses its contents when power is removed (ordinary RAM). Non-volatile memory retains data (ROM, flash, SSD, HDD). “Read-only” in ROM is a historical umbrella term; modern flash/EEPROM can be electrically rewritten.

  • SRAM: uses bistable circuits/flip-flops, fast and costly; commonly used in cache.
  • DRAM: stores bits as charge in capacitors and requires refresh; commonly used as main memory.
  • PROM: programmed once by the user/manufacturer.
  • EPROM: erased using ultraviolet light and reprogrammed.
  • EEPROM: electrically erasable and reprogrammable; flash is a block-erasable form.
  • Virtual memory: gives processes a virtual address space and allows inactive pages to reside on secondary storage. It is not equivalent to adding physical RAM; page faults and disk access can be much slower.
  • Cache mapping: direct-mapped, fully associative and set-associative. In an n-way set-associative cache, each set contains n possible cache lines.

Storage access: magnetic tape is a classic sequential-access medium; disks and SSDs support direct/random access at the logical block level.

Memory capacity calculations: number of addressable locations = \(2^n\) for n address bits. A memory organised as \(2K \times 16\) has 2K words, each 16 bits; address lines = \(\log_2(2K)\), while data lines = 16. Check whether K is being used as 1024 in the question.

4. CPU organisation, buses and instruction execution

The Central Processing Unit (CPU) executes program instructions. Its principal functional units are the Arithmetic Logic Unit (ALU), Control Unit (CU) and register set. The CPU is often described as the “brain” of the computer; the control unit coordinates the instruction cycle and sends control signals.

  • ALU: performs arithmetic (addition, subtraction, etc.) and logical/comparison operations.
  • Control Unit: fetches/decodes instructions and coordinates data movement, timing and execution using control signals. It does not itself perform arithmetic calculations.
  • Registers: very fast storage inside the CPU. Common registers: Program Counter (PC) holds the address of the next instruction; Instruction Register (IR) holds the current instruction; accumulator stores intermediate arithmetic/logic results; MAR holds a memory address; MDR/MBR holds data being transferred; status/flag register records conditions such as zero, carry, sign and overflow.

System bus: a collection of communication lines connecting CPU, memory and I/O. The address bus identifies a memory/I/O location (commonly CPU-to-device direction); the data bus carries data (typically bidirectional); the control bus carries read/write, interrupt, clock and other control signals. Bus width and address width are different concepts.

Instruction cycle

  1. Fetch: PC supplies the instruction address; instruction is read from memory into IR; PC is advanced.
  2. Decode: control unit interprets the opcode and addressing mode.
  3. Operand fetch: required operands are obtained from registers or memory.
  4. Execute: ALU or another execution unit performs the operation.
  5. Write-back: result is stored in a register or memory; flags may be updated.
  6. Interrupt check: processor may service a pending enabled interrupt before the next instruction.

Some textbooks combine or rename stages. Pipelining overlaps stages of different instructions; it improves throughput but does not necessarily reduce the latency of one instruction.

Instruction Set Architecture (ISA) and processor styles

ISA is the programmer-visible contract between software and processor hardware: instruction set, registers, data types, addressing modes, memory model and exception/interrupt behaviour. Microarchitecture is the internal implementation of an ISA. RISC generally favours a smaller, simpler instruction set and regular instruction formats; CISC generally offers more complex instructions. Real processors blur this distinction.

Von Neumann architecture uses a shared memory/address space for instructions and data; Harvard architecture uses separate instruction and data memories/buses. Parallel processing uses multiple processing elements. Distributed systems consist of networked independent computers; do not confuse “distributed” with the classic tightly/loosely coupled multiprocessor classifications without checking the exact wording.

Machine instruction fields: opcode specifies the operation; operand/address fields identify data or locations. An assembler translates symbolic assembly mnemonics into machine code. A pseudo-instruction is an assembler-level convenience and may expand into one or more actual machine instructions.

5. Data representation, memory units and character encoding

All digital computer data are represented internally using bits (0 and 1). A bit is one binary digit; a byte is conventionally 8 bits. A nibble is 4 bits. Word size is processor/architecture dependent.

6. Software categories, translators and basic IT concepts

Software is the collection of programs, procedures and related data that instructs a computer. Hardware is the physical equipment; software is the logical/programmatic component.

  • System software: operates/manages the computer and provides a platform (operating system, device drivers, language translators and system utilities). It is not accurate to say all system software must be written in one particular programming language.
  • Application software: supports end-user tasks, e.g. word processing, spreadsheets, browsers, presentation and accounting packages. It may be general-purpose or customised.
  • Utility software: maintenance/security tools such as backup, compression, disk checking and antivirus.
  • Firmware: low-level software stored in non-volatile memory to control embedded devices.
  • Open-source software: distributed under a licence that grants rights to inspect, use, modify and redistribute source code, subject to licence terms. “Freeware” does not automatically mean open source.

Final rapid revision

  • Vacuum tube → first generation; transistor → second; IC → third; microprocessor → fourth.
  • ALU performs arithmetic/logic; Control Unit coordinates the instruction cycle.
  • PC points to the next instruction; IR holds the current instruction.
  • Address bus identifies a location; data bus carries data; control bus carries control signals.
  • Registers → cache → RAM → secondary storage is the broad speed/capacity hierarchy.
  • SRAM is commonly used for cache; DRAM is commonly used for main memory.
  • EPROM is erased by ultraviolet light; EEPROM is electrically erasable.
  • Magnetic tape is sequential access; disk/SSD storage supports direct access.
  • ASCII is 7-bit in its original standard; EBCDIC is 8-bit; Unicode is a character repertoire with UTF encodings.
  • Compiler translates; interpreter executes through a runtime; assembler translates assembly language.
  • ISA is the software-visible processor interface; microarchitecture is its internal implementation.
