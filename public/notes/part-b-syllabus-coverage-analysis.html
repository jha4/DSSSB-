2. Workbook quality

  • 1,659 distinct normalized question stems; 211 additional rows are exact normalized repeats across 179 duplicate groups. Repeated rows are retained with source exam/year/shift metadata.
  • 1,391 records contain all four option texts. 479 records have at least one missing option field; 362 have all four separate option fields blank.
  • Four records have no explanation text and one record has no answer key. Missing fields are shown as missing rather than completed by guesswork.
  • Answer keys use letter forms (A–D) and numeric forms (1–4). Numeric keys are displayed as A–D while the original key is retained in the rendered card.

3. Mapping and syllabus gaps

The workbook uses multiple labels for related subjects (for example, DBMS and DBMS & SQL; Computer Organization and Computer organisation; Web Technology and Web technologies). These are consolidated for the chapter totals. “Other CS / general” and “Artificial Intelligence” are not explicit standalone headings in the supplied Part B syllabus, so their 59 records remain in a supplementary chapter.

Small workbook counts for Teaching Methodology (3) and MIS/Expert Systems (1) do not make those syllabus areas unimportant. Their theory sections are included according to the syllabus, not weighted only by PYQ frequency.

4. Revision priority — evidence versus syllabus

  • High-volume practice: Programming/OOP, Networks/Security, Computer Fundamentals/Architecture, Digital Electronics, OS, Algorithms/Data Structures, DBMS and Web Technology have the largest record counts.
  • Still cover the full syllabus: Software Engineering, Graphics/Multimedia/Mobile, Business/E-Commerce/KM, Mathematics/Statistics, Teaching Methodology and MIS/DSS/Expert Systems remain explicit syllabus units even with fewer workbook records.
  • Use counts to allocate extra practice, not to exclude topics. The question bank is not a statistically validated prediction of the next paper.

5. How questions are displayed

Each Part B question card includes the full stem, the four option fields when supplied, the mapped correct answer, the source explanation and available exam/year/shift/topic metadata. Missing source fields are explicitly identified. Exact duplicate rows are not silently removed.

6. Syllabus gap audit and updates

A second pass compared the exact supplied syllabus wording with the existing chapter notes. The following areas were expanded where the original notes were too brief or did not name the syllabus concept explicitly:

  • Operating Systems & Linux: Linux permission semantics for files/directories, octal and symbolic chmod, ownership, umask, SUID/SGID/sticky bit, ACLs, authentication versus authorization, file/process commands, shell pipes/redirection, GNU/Linux distributions, GPL and permissive licences, and package managers.
  • DBMS: ER entities/attributes/relationships and cardinality, ER-to-relational mapping, ISAM and overflow areas, sequential/indexed/direct organization, volatile versus non-volatile storage, data dictionary and data independence.
  • Algorithms & Programming: formal O/Ω/Θ definitions, flowchart symbols, pseudocode and program dry-runs.
  • Teaching Methodology: child development, individual differences, learning difficulties, remedial support and inclusive classroom strategies.
  • Web Technology: forward/reverse proxy, publishing workflow, browser developer tools and JavaScript callbacks.
  • Graphics: curve/surface representations, B-rep, CSG, voxel-based solid modelling and the viewing pipeline.
  • MIS/DSS: DSS user-interface, database, model-base and knowledge-base components, plus what-if, sensitivity and goal-seeking analysis.

These are theory additions based on the supplied syllabus. They do not create new PYQs or alter the source answer keys. The PYQ bank continues to show only options, keys and explanations actually present in the workbook; absent source fields remain identified as missing.
