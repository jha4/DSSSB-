URLs, Protocols, E-mail and Web Security

URL and domain names

URL (Uniform Resource Locator) identifies a resource and the method/location used to access it. Example: https://example.com:443/docs/page.html?mode=read#top.

  • Scheme: https — protocol/access scheme.
  • Host: example.com — domain/hostname.
  • Port: 443 — optional service endpoint port.
  • Path: /docs/page.html — resource path.
  • Query: ?mode=read — parameters sent with the request.
  • Fragment: #top — client-side reference within the resource.

DNS (Domain Name System) resolves domain names to IP addresses. A domain name is a human-readable name; hosting is the infrastructure that stores/runs the site. They are not the same thing.

HTTP and HTTPS

HTTP (Hypertext Transfer Protocol) is an application-layer request/response protocol. It is stateless by default: each request is independent unless state is added through cookies, tokens or server-side sessions.

HTTPS is HTTP protected by TLS. TLS provides confidentiality (encryption), integrity and authentication of the server when certificates are correctly validated. SSL is the older predecessor; modern deployments should use TLS.

E-mail protocols and mailto

  • SMTP: sends/submits and relays email.
  • POP3: retrieves email, traditionally by downloading messages from a server.
  • IMAP: accesses and synchronises messages stored on a mail server.
  • mailto: a URI scheme that opens an email composition action, for example mailto:help@example.com.
  • To: primary recipient; CC: visible copy recipient; BCC: recipient hidden from other recipients.

Proxy servers and security basics

A forward proxy acts on behalf of clients, for example to filter or cache outbound requests. A reverse proxy sits in front of origin servers and may provide TLS termination, load balancing, caching and routing.

  • Cookie: small data stored by a browser and sent with matching requests; often used for session identifiers and preferences.
  • Session: server-side state associated with a client, commonly referenced by a session cookie or token.
  • Authentication: verifies who a user is; authorisation determines what that user may do.
  • XSS: injection of untrusted script into pages viewed by users; mitigate with output encoding, safe DOM APIs and content security controls.
  • CSRF: tricks an authenticated browser into making an unwanted request; use anti-CSRF tokens, SameSite cookies and appropriate request checks.
  • Use HTTPS, secure cookie attributes, input validation, output encoding, access controls and timely updates. Client-side validation alone is not a security boundary.
Exam traps: HTTP is not encrypted by itself; HTTPS uses TLS. SMTP sends, POP3/IMAP retrieve. BCC hides recipients. A URL contains a scheme and host; a path identifies a resource.

    Which protocol allows users to securely access web pages using encryption?

    1. A. HTTP
    2. B. HTTPS
    3. C. FTP
    4. D. DNS

    Correct answer: B. HTTPS

    Explanation (workbook): Core Concept: HTTPS (Hypertext Transfer Protocol Secure) allows users to access web pages securely by encrypting the communication between the client and web server, typically using TLS.

    Why other options are incorrect: HTTP does not provide encryption by itself. FTP is used for file transfer, while DNS is used to translate domain names into IP addresses.

  2. PYQ #11 · 2021 · DSSSB TGT Computer Science

    Which of the following is/are (a) part(s) of a U.R.L.?
    I. Protocol
    II. Hostname
    III. Directory and filename

    1. A. II and III
    2. B. I and II
    3. C. I, II and III
    4. D. I and III

    Correct answer: C. I, II and III

    Explanation (workbook): Core Concept: A URL (Uniform Resource Locator) is a reference to a web resource that specifies its location on a computer network and a mechanism for retrieving it. A typical URL consists of several parts:
    I. Protocol: Correct (e.g., `http://`, `https://`, `ftp://`). It specifies how the resource is accessed.
    II. Hostname: Correct (e.g., `www.example.com`). It identifies the server where the resource is located.
    III. Directory and filename: Correct (e.g., `/path/to/page.html`). This specifies the exact location of the resource on the server.
    All three are essential parts of a complete URL.

    Why other options are incorrect: Options A, B, and D are incorrect because they exclude one or more of the valid components of a URL. A complete URL typically includes the protocol, hostname, and the specific path (directory and filename) to the resource.

  3. PYQ #51 · 2021 · DSSSB TGT Computer Science

    ______ gives the location of a resource on the internet.

    1. A. Domain name
    2. B. TCP/IP
    3. C. URL
    4. D. IP address

    Correct answer: C. URL

    Explanation (workbook): Core Concept: A URL (Uniform Resource Locator) is a specific string of characters that provides the address of a resource on the Internet and the protocol used to access it. It uniquely identifies and gives the location of a resource, such as a web page, image, or file.

    Why other options are incorrect: A Domain Name (A) is part of a URL but doesn't give the full location or protocol. TCP/IP (B) is a suite of communication protocols, not a resource locator. An IP address (D) is a numerical label assigned to devices on a network, which can be part of a URL, but a URL provides a more complete and user-friendly way to locate a resource.
