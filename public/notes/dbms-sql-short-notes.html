Database Management Systems and SQL — Complete Notes

Coverage: DBMS concepts, relational model, keys, constraints, SQL, normalization, indexing, transactions, concurrency, recovery and security.

1. DBMS fundamentals

A database is an organized collection of related data. A DBMS defines, creates, stores, queries, updates and controls access to databases. It supports sharing, controlled redundancy, integrity, security, backup and recovery.

  • Schema: logical design/structure. Instance: actual data at a particular moment.
  • Data independence: ability to change one schema level without requiring changes at the next higher level. Physical data independence separates storage changes from logical schema; logical data independence separates logical schema changes from user views.
  • Metadata: data about data. A data dictionary/catalog stores definitions of tables, columns, constraints, users and database objects.

2. Relational terminology and keys

  • Relation: table. Tuple: row. Attribute: column. Domain: permitted values for an attribute.
  • Primary key: chosen candidate key identifying each row; unique and not null. Candidate key: minimal attribute set that uniquely identifies a tuple. Superkey: any attribute set that uniquely identifies a tuple, possibly with extra attributes.
  • Alternate key: candidate key not selected as primary. Foreign key: attribute(s) referencing a key in another or the same table. Composite key: consists of multiple attributes.

3. Integrity constraints

  • Domain constraint: values must belong to the attribute domain.
  • Entity integrity: primary key values are unique and not null.
  • Referential integrity: foreign-key values must match a referenced key or be null where permitted.
  • CHECK, UNIQUE, NOT NULL, PRIMARY KEY and FOREIGN KEY constraints enforce data rules.

WHERE filters rows before grouping; GROUP BY forms groups; HAVING filters groups; ORDER BY sorts results. Aggregates include COUNT, SUM, AVG, MIN and MAX. COUNT(*) counts rows; COUNT(column) ignores NULL values.

5. Joins and subqueries

  • INNER JOIN: matching rows from both inputs. LEFT JOIN: all left rows plus matches; unmatched right values become NULL. RIGHT and FULL OUTER JOIN retain the corresponding right or both sides.
  • CROSS JOIN: Cartesian product. SELF JOIN: joins a table to itself using aliases.
  • Subquery: query nested inside another query. A correlated subquery refers to the outer query row.

6. Functional dependencies and normalization

A functional dependency X→Y means each value of X determines exactly one value of Y. Normalization reduces update, insertion and deletion anomalies.

Normal formCore condition
1NFAtomic attribute values; no repeating groups
2NF1NF and no partial dependency of a non-prime attribute on part of a candidate key
3NF2NF and no problematic transitive dependency; for each non-trivial X→A, X is a superkey or A is prime
BCNFFor each non-trivial X→Y, X is a superkey

7. Transactions, concurrency and recovery

A transaction is a logical unit of work. ACID means Atomicity (all-or-nothing), Consistency (preserves constraints), Isolation (safe concurrent behaviour) and Durability (committed effects survive failures).

  • Concurrency control: manages simultaneous transactions using locks, timestamps or optimistic methods.
  • Serializability: a concurrent schedule is equivalent to a serial order under the selected criterion.
  • Deadlock: transactions wait cyclically for resources/locks. Systems may prevent, detect or recover from deadlocks.
  • Recovery: logs, checkpoints and undo/redo restore a consistent state after failure.

8. Indexing, storage and security

  • Index: auxiliary structure speeding retrieval at storage/update cost. B/B+ trees support ordered/range access; hash indexes suit equality lookup.
  • Sequential organization: records stored in key order. Indexed: index maps keys to records. Direct/hashed: computes location from a key.
  • Database security uses authentication, authorization, least privilege, encryption, auditing, backup and parameterized queries to reduce SQL injection risk.

9. Exam traps

  • DROP removes an object; DELETE removes selected rows; TRUNCATE removes rows but retains the table definition.
  • WHERE filters rows; HAVING filters groups. BCNF is stricter than 3NF.
  • Primary key is a selected candidate key; foreign key enforces a reference.
