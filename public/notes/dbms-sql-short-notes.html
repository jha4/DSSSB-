Detailed theory and topic-wise PYQs

1. DBMS fundamentals and architecture

A database is an organised collection of logically related data. A Database Management System (DBMS) is software that defines, creates, stores, retrieves, updates and administers that data. It provides controlled sharing, integrity enforcement, access control, concurrency management, backup and recovery.

Schema is the database design or structure; an instance is the actual data present at a particular time. Metadata describes data: table and column names, data types, constraints, indexes, users and object definitions. A catalogue/data dictionary stores this metadata.

The three-schema architecture separates external views, the conceptual/logical schema and the internal/physical schema. Physical data independence means storage-level changes need not alter the conceptual schema. Logical data independence means conceptual changes need not force changes to every external view or application; it is generally harder to achieve.

Common database models include hierarchical (tree/parent-child), network (graph-like records and links), relational (tables), object-oriented and object-relational. Relational databases represent data primarily through relations (tables).

2. Relational model, relational algebra and constraints

A relation is a table; a tuple is a row; an attribute is a column; and a domain is the permitted set/type of values for an attribute. A relation schema describes its attributes and constraints. A relation instance is its current set of tuples.

Relational algebra operations: selection (σ) filters rows; projection (π) selects columns; union (∪) combines union-compatible relations; set difference (−) returns tuples in the first relation but not the second; Cartesian product (×) pairs every tuple of one relation with every tuple of another. Joins combine related tuples based on a condition.

Domain constraint restricts attribute values to a domain. Entity integrity requires a primary key to be unique and non-NULL. Referential integrity requires a foreign-key value to match a referenced candidate/primary key value, or be NULL where allowed. CHECK, UNIQUE, NOT NULL, PRIMARY KEY and FOREIGN KEY are common SQL constraints.

Q. Consider the relation R (PQRSTU) with the set of functional dependencies F = {P -> RT, Q -> S, R -> PS, QS -> TU}. Find the closure of PQ.

  1. A. PQRST
  2. B. PQRTU
  3. C. PQRSU
  4. D. PQRSTU

Correct answer: Option D

Explanation (workbook): Core Concept: To find the closure of PQ (denoted as (PQ)+), we start with the attributes P and Q. We then iteratively apply the given functional dependencies (FDs) to add new attributes until no more can be added:
1. Start with {P, Q}.
2. From P -> RT, add R and T. Set becomes {P, Q, R, T}.
3. From Q -> S, add S. Set becomes {P, Q, R, S, T}.
4. From R -> PS, R is in the set, P and S are already in the set. No new attributes.
5. From QS -> TU, Q and S are in the set, so add T and U. Set becomes {P, Q, R, S, T, U}.
Since no more attributes can be added, the closure of PQ is PQRSTU.

Why other options are incorrect: The other options (PQRST, PQRTU, PQRSU) are incomplete closures. They miss one or more attributes that can be derived from the initial set PQ and the given functional dependencies. For example, PQRST misses U, PQRTU misses S, and PQRSU misses T.

3. Keys and functional dependencies

A superkey is any attribute set that uniquely identifies a tuple; it may contain unnecessary attributes. A candidate key is a minimal superkey. One candidate key is selected as the primary key; remaining candidate keys are alternate keys. A foreign key references a key in another or the same relation. A composite key contains more than one attribute.

A functional dependency X → Y means each value of X determines exactly one value of Y. X is the determinant (left-hand side); Y is the dependent (right-hand side). Attribute closure X⁺ is the set of attributes functionally determined by X under the given dependencies. To compute closure, start with X and repeatedly add Y whenever the current set contains all attributes of a dependency's left side.

Armstrong's inference axioms are reflexivity (if Y ⊆ X, then X → Y), augmentation (if X → Y, then XZ → YZ) and transitivity (if X → Y and Y → Z, then X → Z). Union, decomposition and pseudotransitivity are derived rules.

4. ER modelling

An entity is a distinguishable real-world object or concept. An entity set/type groups entities of the same kind. An attribute describes an entity or relationship; attributes may be simple/composite, single-valued/multivalued, stored/derived or key attributes. A relationship is an association among entities.

ER cardinality includes 1:1, 1:N and M:N. Participation may be total (every entity must participate) or partial (participation is optional). A weak entity cannot be uniquely identified by its own attributes alone; it depends on an owner entity and is identified using its partial key together with the owner's key. In Chen notation, a weak entity is shown by a double rectangle, a relationship by a diamond, and a multivalued attribute by a double ellipse.

When mapping ER to relations, strong entities generally become tables. A 1:N relationship is commonly represented by a foreign key on the N-side. An M:N relationship generally becomes a junction table containing foreign keys to the participating entity tables. Descriptive attributes belong to the relationship when they describe the association itself.

5. SQL: language classes, queries and functions

SQL (Structured Query Language) is used to define, query and manipulate relational databases. Common command groups: DDL defines objects (CREATE, ALTER, DROP, TRUNCATE); DML retrieves or changes rows (SELECT, INSERT, UPDATE, DELETE); DCL controls permissions (GRANT, REVOKE); TCL controls transactions (COMMIT, ROLLBACK, SAVEPOINT).

SELECT retrieves data. SELECT * requests all columns. WHERE filters rows before grouping; GROUP BY forms groups; HAVING filters groups; ORDER BY sorts output. Aggregate functions include COUNT, SUM, AVG, MIN and MAX. COUNT(*) counts rows; COUNT(column) ignores NULL values. LIKE performs pattern matching (often using % for any sequence and _ for one character). Comparison operators include =, <>, <, >, <= and >=.

Joins: INNER returns matching rows; LEFT OUTER preserves all left rows; RIGHT OUTER preserves all right rows; FULL OUTER preserves rows from both sides; CROSS produces a Cartesian product; SELF JOIN joins a table to itself. A subquery is nested inside another query. DEFAULT supplies a value when one is not specified; it does not mean NOT NULL. SQL dialects differ: date/time functions and exact data types are vendor-specific, so read the question's stated DBMS context carefully.

6. Normalisation

Normalisation organises relations to reduce redundancy and insertion, update and deletion anomalies. A functional dependency is central to identifying which attributes determine others.

  • 1NF: attributes contain atomic values; no repeating groups or relation-valued attributes.
  • 2NF: in 1NF and every non-prime attribute is fully functionally dependent on every candidate key; no partial dependency on a proper subset of a candidate key.
  • 3NF: for every non-trivial X → A, X is a superkey or A is a prime attribute. This formal test is safer than the shorthand “no transitive dependency”.
  • BCNF: for every non-trivial X → Y, X must be a superkey. BCNF is stricter than 3NF.

A relation in 2NF is necessarily in 1NF, but not necessarily in 3NF. Always derive candidate keys and prime attributes before deciding the highest normal form.

7. Transactions, concurrency and recovery

A transaction is a logical unit of database work. ACID: Atomicity (all or nothing), Consistency (preserves integrity rules), Isolation (concurrent execution behaves according to the isolation guarantee) and Durability (committed effects survive failures).

A schedule is conflict serializable if its precedence graph is acyclic. Build the graph by adding an edge Ti → Tj when conflicting operations (same data item, different transactions, at least one write) occur in Ti before Tj. A cycle means the schedule is not conflict serializable.

Concurrency-control methods include locking and timestamp ordering. A timestamp is an ordering identifier assigned to a transaction. Deadlock occurs when transactions wait in a cycle for resources. Recovery uses logs, undo/redo, checkpoints or shadow paging. A checkpoint is a synchronization/recovery point that limits the work needed after a failure; shadow paging is an alternative recovery approach to log-based schemes.

8. Distributed databases, file organisation and indexing

A distributed database stores logically related data across multiple networked sites. Fragmentation divides a relation into logical pieces (horizontal, vertical or hybrid); allocation decides which site stores each fragment; replication stores copies at multiple sites. These are distinct design decisions.

Sequential file organisation stores records in sequence and is suited to batch processing; insertion/deletion can be expensive because order may need to be maintained. Direct/random access computes or directly addresses a record location. Indexed organisation uses an auxiliary index. ISAM combines ordered sequential storage with an index and overflow areas. DASD means Direct Access Storage Device. Volatility describes how frequently file contents change; it is not the same as whether storage is volatile memory.

An index speeds retrieval at the cost of storage and update overhead. Primary indexes are associated with ordering on a primary key; secondary indexes provide additional access paths. B/B+ trees support ordered and range queries; hashing is typically suited to equality lookups. Read each question's exact index definition rather than relying only on the label.

OLTP supports frequent operational transactions and prompt responses, typically with many short inserts/updates. OLAP supports analytical queries over large historical datasets and summarisation.
