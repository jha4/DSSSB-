1. Algorithm fundamentals and problem solving

Definition: An algorithm is a finite sequence of well-defined, unambiguous and effective steps that transforms valid input into the required output. An algorithm describes the method of solving a problem, independent of a particular programming language.

Characteristics of an algorithm

  • Input: Zero or more clearly specified values.
  • Output: At least one result.
  • Definiteness: Every step must be precise and unambiguous.
  • Finiteness: It must terminate after a finite number of steps.
  • Effectiveness: Each operation must be basic enough to be carried out exactly in finite time.
  • Generality: It should solve all valid instances of the intended problem class.

Problem-solving and program-design steps

  1. Understand the problem, constraints and expected behaviour.
  2. Identify inputs, outputs, assumptions and edge cases.
  3. Choose an appropriate strategy and data structure.
  4. Break the solution into modules (top-down design).
  5. Represent the logic using pseudocode or a flowchart.
  6. Dry-run with normal, boundary and invalid inputs.
  7. Implement, test, debug, analyse and refine.

Pseudocode is a structured, language-independent way to express an algorithm. It resembles programming constructs but does not require the syntax of a particular language. A flowchart is a graphical representation of an algorithm or process.

Top-down design decomposes a large problem into smaller subproblems. Modular programming organises a program into cohesive modules with clear interfaces. A good module has high cohesion (related tasks within it) and low coupling (limited dependency on other modules).

2. Analysis of algorithms and complexity

Definition: Algorithm analysis estimates the resources an algorithm needs as input size n grows. It focuses on growth rates rather than the execution time measured on one particular computer.

  • Time complexity: Growth in the number of elementary operations as a function of input size.
  • Space complexity: Growth in memory requirement. Auxiliary space is extra memory used beyond the input representation.
  • Best case: Minimum work over inputs of size n.
  • Average case: Expected work under an explicitly assumed input distribution.
  • Worst case: Maximum work over inputs of size n.

Loop-counting rules

  • A loop that advances by 1 up to n generally performs O(n) iterations.
  • Two independent nested loops of n iterations each generally perform O(n²) work.
  • A loop that doubles or halves its control variable each iteration generally performs O(log n) iterations.
  • Consecutive loops add their costs; retain the dominant term.
  • Nested loop bounds must be read carefully; not every pair of nested loops is O(n²).

Recurrence relations and Master Theorem

Recursive algorithms are often described by a recurrence. For T(n) = aT(n/b) + f(n), compare f(n) with nlogba:

  • Case 1: If f(n) is polynomially smaller, T(n) = Θ(nlogba).
  • Case 2: If f(n) has the same order up to a logarithmic factor, an additional logarithmic factor appears. In the common form f(n)=Θ(nlogba logkn), T(n)=Θ(nlogba logk+1n).
  • Case 3: If f(n) is polynomially larger and the regularity condition holds, T(n)=Θ(f(n)).

Always check the theorem's conditions; it does not apply to every recurrence.

3. Searching algorithms

Linear (sequential) search

Linear search compares the key with elements one by one, from the beginning, until it is found or the collection ends. It works on sorted and unsorted data.

  • Best case: O(1), when the first element matches.
  • Average and worst case: O(n), because a linear number of elements may be inspected.
  • Iterative auxiliary space: O(1).

Binary search

Binary search repeatedly compares the target with the middle element of the current interval and discards the half that cannot contain the target. It requires sorted data and efficient access to the middle element; this is why it is natural for arrays but generally inefficient for linked lists.

  • Time complexity: O(log n) in best/average/worst asymptotic analysis; best case is O(1) when the first middle comparison succeeds.
  • Iterative auxiliary space: O(1). Recursive implementation uses O(log n) call-stack space.
  • Maintain a correct search interval and ensure the loop makes progress; use a safe midpoint expression such as low + (high − low) / 2.

4. Sorting algorithms

Sorting arranges records in ascending or descending order according to a key. A stable sort preserves the relative order of records with equal keys. An in-place sort uses only a small amount of additional memory (implementation details may vary).

How the main sorts work

  • Bubble sort: Repeatedly compare adjacent elements and swap if out of order. After each complete pass, the largest remaining item reaches its final position at the end. With an early-exit flag, an already sorted input can finish in O(n).
  • Selection sort: Find the smallest item in the unsorted suffix and swap it into the next position. It performs O(n²) comparisons even when input is already sorted; swaps are O(n).
  • Insertion sort: Maintain a sorted prefix and insert the next element into its correct position. Efficient for small or nearly sorted data; stable in the standard implementation.
  • Merge sort: Divide the array into halves, recursively sort each half, then merge. Time O(n log n); array implementation typically needs O(n) auxiliary space.
  • Quick sort: Choose a pivot, partition values around it, then recursively sort partitions. Good average performance, but poor pivot choices can produce O(n²) worst case.
  • Radix sort: Sort keys digit by digit (least-significant-digit or most-significant-digit approach). It is not comparison-based; stable sorting at each digit is essential for the usual LSD method.

5. Recursion and divide and conquer

Recursion occurs when a function solves a problem by calling itself on a smaller instance. Every correct recursive solution needs a base case and progress toward that base case; otherwise it may recurse indefinitely or overflow the call stack.

  • Base case: Smallest case solved directly.
  • Recursive case: Reduces the problem to one or more smaller subproblems.
  • Call stack: Stores activation records such as parameters, local variables and return addresses.
  • Tail recursion: The recursive call is the final operation in the function; some language implementations can optimise it, but do not assume all runtimes do.

Divide and conquer has three stages: divide a problem into smaller subproblems, conquer them recursively, and combine their solutions. Merge sort and quicksort are classic examples; binary search is a decrease-and-conquer style method often grouped with divide-and-conquer in introductory syllabi.

Not every algorithm that repeatedly processes data is divide and conquer. Dynamic programming stores solutions to overlapping subproblems; greedy algorithms make locally optimal choices; backtracking explores choices and abandons paths that cannot lead to a valid solution.

6. Greedy algorithms

Definition: A greedy algorithm constructs a solution step by step, choosing what appears to be the best local option at each step, without reconsidering earlier choices.

  • Greedy-choice property: A globally optimal solution can be reached by making a locally optimal choice first.
  • Optimal substructure: An optimal solution contains optimal solutions to relevant subproblems.
  • Both properties (or a suitable proof) are needed before assuming a greedy method is correct.
  • Examples: Kruskal's and Prim's minimum spanning tree algorithms, Dijkstra's shortest-path algorithm for non-negative edge weights, and Huffman coding.

A greedy choice is not always globally optimal. For example, a naive coin-change strategy can fail for some coin denominations. The algorithm must be justified for the specific problem.

7. Dynamic programming and backtracking

Dynamic programming (DP) solves problems with overlapping subproblems and optimal substructure by storing subproblem results so they are not recomputed repeatedly.

  • Memoization: Top-down recursion plus a cache of previously computed results.
  • Tabulation: Bottom-up computation in a table, following dependency order.
  • Typical problems: Fibonacci with caching, 0/1 knapsack, longest common subsequence and matrix-chain multiplication.
  • DP is not simply recursion: the key is reuse of overlapping subproblem results.

Backtracking explores a decision tree of partial solutions. It extends a candidate while it remains feasible and abandons a branch when it violates constraints or cannot produce a valid solution. Examples include N-Queens, subset sum and permutations.

8. Graph algorithms: traversal, shortest path and MST

Breadth-first and depth-first search

  • BFS: Uses a queue; explores vertices in layers. In an unweighted graph, it finds shortest paths measured by number of edges. Adjacency-list complexity is O(V+E).
  • DFS: Uses recursion or an explicit stack; explores deeply before backtracking. Adjacency-list complexity is O(V+E). Useful for cycle detection, connected components and articulation points.

Shortest-path algorithms

  • Dijkstra: Single-source shortest paths when edge weights are non-negative. A priority queue implementation commonly runs in O((V+E) log V) with adjacency lists and a binary heap.
  • Bellman–Ford: Handles negative edge weights and can detect a reachable negative-weight cycle; O(VE).
  • Floyd–Warshall: All-pairs shortest paths; O(V³) time and O(V²) space in its standard form. It can handle negative edges but not negative cycles in a meaningful shortest-path result.

Minimum spanning tree (MST)

A spanning tree of a connected, undirected graph connects all vertices without cycles and contains V−1 edges. A minimum spanning tree has the minimum possible total edge weight.

  • Kruskal: Sort edges by weight and add the next lightest edge that does not form a cycle; disjoint-set union helps detect cycles.
  • Prim: Grow one tree by repeatedly adding the minimum-weight edge crossing from the current tree to an unvisited vertex.
  • An MST is not the same as a shortest-path tree: MST minimises total weight of the selected connecting edges, while shortest-path algorithms minimise distance from a source.

9. Algorithm exam checklist and quick comparisons

  • Binary search requires sorted data; linked lists do not provide constant-time middle access.
  • Bubble, selection and insertion sort have O(n²) worst-case time; merge sort has O(n log n) worst-case time.
  • Standard quicksort has O(n log n) average and O(n²) worst-case time.
  • Big-O is an upper bound, Ω a lower bound and Θ a tight bound.
  • Stack = LIFO; queue = FIFO; BFS uses a queue; DFS uses a stack/recursion.
  • Greedy chooses locally; DP stores overlapping subproblem results; backtracking explores and prunes choices.
  • MST connects all vertices with minimum total edge weight; shortest path minimises route cost from a source.
