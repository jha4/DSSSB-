XML, DTD and XML Parsers

XML fundamentals

XML (Extensible Markup Language) is a text-based markup format for storing and transporting structured data using user-defined tags. It is case-sensitive and is not primarily a presentation language.

<?xml version="1.0" encoding="UTF-8"?>
<catalog>
  <book id="b1">
    <title>Web Technology</title>
  </book>
</catalog>
  • An XML document has exactly one root element containing the other elements.
  • Elements must be properly nested and have matching start/end tags; attribute values must be quoted.
  • Names are case-sensitive, cannot contain spaces and cannot start with a digit. Names beginning with the reserved XML prefix should be avoided.
  • Comments use <!-- comment -->; the sequence -- cannot occur inside a comment.
  • Attributes provide metadata; uniqueness constraints depend on declared types/schema rules (for example, DTD ID).

Well-formed vs valid XML

Well-formed: follows XML syntax rules. Valid: is well-formed and also conforms to a declared DTD or XML Schema.

DTD and XML Schema (XSD)

  • DTD (Document Type Definition) declares allowed elements, attributes, entities and structural relationships. DTD has limited datatype support.
  • External DTD: declared with a DOCTYPE such as <!DOCTYPE catalog SYSTEM "catalog.dtd">.
  • Internal DTD subset: declarations appear inside square brackets within the DOCTYPE declaration.
  • XML Schema / XSD: XML-based schema language supporting richer data types, namespaces, occurrence limits and constraints.

XML parsers

Parser/modelHow it works
DOMLoads/builds a tree representation of the document in memory; convenient for random access and modification.
SAXEvent-driven, sequential parsing; processes events as data is read and does not require a complete in-memory tree.
XML processorReads XML and makes its content/structure available to an application.

DTD element declarations use forms such as <!ELEMENT catalog (book*)>. XML Schema defines element/attribute types and constraints. Namespaces distinguish elements with the same local name from different vocabularies.

Additional syllabus coverage

  • XPath: selects nodes/values in an XML document.
  • XSLT: transforms XML into another format, often HTML or another XML document.
  • Web services: may use XML-based SOAP messages or REST-style HTTP APIs; XML is common in SOAP and configuration/interchange formats.
Exam traps: XML is case-sensitive; one root element; DTD has limited datatypes; XSD supports rich datatypes; DOM builds a tree; SAX is event-driven.

  1. PYQ #6 · 2023 · DSSSB TGT Computer Science

    _______ reads XML documents and provides access to their content and structure.

    1. A. XML schema
    2. B. XML pre-processor
    3. C. XML processor
    4. D. XML codes

    Correct answer: C. XML processor

    Explanation (workbook): Core Concept: An XML processor (also known as an XML parser) is a software module that reads XML documents and provides access to their content and structure to an application. It checks for well-formedness and optionally validates the document against a schema.

    Why other options are incorrect: An XML schema defines the legal building blocks of an XML document, but it doesn't read or process the document itself. An XML pre-processor is not a standard term. XML codes is a vague term and doesn't refer to a component that reads documents.

  2. PYQ #20 · 2023 · DSSSB TGT Computer Science

    Which of the following is NOT an XML Parser?

    1. A. Shell
    2. B. JDOM
    3. C. DOM
    4. D. SAX

    Correct answer: A. Shell

    Explanation (workbook): Core Concept: XML Parsers are software libraries or programs that read XML documents and provide access to their content and structure. DOM (Document Object Model) and SAX (Simple API for XML) are two fundamental types of XML parsers, while JDOM is a Java-specific API that provides a simpler way to work with XML documents than DOM. A 'Shell' (like Bash, Zsh, etc.) is a command-line interpreter and operating system interface, not an XML parser.

    Why other options are incorrect: 'JDOM' is a Java-based API for XML processing and acts as an XML parser. 'DOM' (Document Object Model) is a tree-based XML parser that allows programmatic access to the document's structure. 'SAX' (Simple API for XML) is an event-driven XML parser. All three are legitimate XML parsing technologies.

  3. PYQ #21 · 2023 · DSSSB TGT Computer Science

    How to write the external DTD?

    1. A. <!DOCTYPE SYSTEM "file-name">
    2. B. <!DOCTYPE element ROOT "file-name">
    3. C. <!DOCTYPE SYSTEM "file-name" root-element>
    4. D. <!DOCTYPE root-element SYSTEM "file-name">

    Correct answer: D. <!DOCTYPE root-element SYSTEM "file-name">

    Explanation (workbook): Core Concept: To declare an external DTD in an XML document, the `DOCTYPE` declaration is used. It specifies the root element of the XML document, followed by the `SYSTEM` keyword, and then the URI (typically a file path or URL) to the external DTD file enclosed in double quotes. The correct syntax is `<!DOCTYPE root-element SYSTEM "file-name">`.

    Why other options are incorrect: `<!DOCTYPE SYSTEM "file-name">` is missing the root element name. `<!DOCTYPE element ROOT "file-name">` uses incorrect keywords and order. `<!DOCTYPE SYSTEM "file-name" root-element>` has the root element in the wrong position.

  4. PYQ #28 · 2023 · DSSSB TGT Computer Science

    Which of the following is a valid syntax for the XML element in a DTD?

    1. A. <!ELEMENT element-name category>
    2. B. <!ATTLIST element-name attribute-name attribute-type attribute-value>
    3. C. <#ELEMENT element-name category>
    4. D. <!ENTITY entity-name "entity-value">

    Correct answer: A. <!ELEMENT element-name category>

    Explanation (workbook): Core Concept: In a Document Type Definition (DTD), `<!ELEMENT element-name category>` is the correct syntax for declaring an XML element. `element-name` is the name of the element, and `category` specifies its content model (e.g., EMPTY, ANY, #PCDATA, or a sequence/choice of child elements).

    Why other options are incorrect: `<!ATTLIST element-name attribute-name attribute-type attribute-value>` is the syntax for declaring an attribute list for an element, not an element itself. `<!ENTITY entity-name "entity-value">` is the syntax for declaring an entity, not an element. `<!#ELEMENT ...>` is syntactically incorrect; the correct syntax uses `<!ELEMENT ...>`.

  5. PYQ #32 · 2023 · DSSSB TGT Computer Science

    Which of the following types of XML parsers is an object that contains all the information of an XML document and is composed like a tree structure?

    1. A. DOS
    2. B. SAX
    3. C. DOM
    4. D. SAY

    Correct answer: C. DOM

    Explanation (workbook): Core Concept: The Document Object Model (DOM) parser for XML creates an in-memory tree structure of the entire XML document. This object-oriented representation contains all the information of the XML document, allowing developers to navigate, access, and modify elements, attributes, and text content programmatically.

    Why other options are incorrect: SAX (Simple API for XML) is an event-based parser that reads the XML document sequentially and triggers events when it encounters elements, attributes, etc. It does not build an in-memory tree structure. 'DOS' and 'SAY' are not standard types of XML parsers.

  6. PYQ #40 · 2023 · DSSSB TGT Computer Science

    Which of the given options best describes the truthfulness of the following statements? i) XML schemas define datatypes for elements and attributes, while DTD doesn't support datatypes. ii) DTD are the declarations that define a document type for SGML. iii) In XML, Tag names can begin with a numeric value.

    1. A. i-True, ii-False, iii-False
    2. B. i-False, ii-True, iii-False
    3. C. i-True, ii-True, iii-False
    4. D. i-False, ii-False, iii-False

    Correct answer: C. i-True, ii-True, iii-False

    Explanation (workbook): Core Concept: Statement (i) is True: XML Schemas (XSD) provide robust data typing capabilities for elements and attributes, allowing for precise validation of data types, whereas DTDs (Document Type Definitions) offer very limited or no explicit support for data types beyond basic character data. Statement (ii) is True: DTDs originated from SGML (Standard Generalized Markup Language) and are used to define the legal structure and content of an XML document. Statement (iii) is False: In XML, tag names (element names) must begin with a letter or an underscore, not a numeric value. They also cannot contain spaces.

    Why other options are incorrect: Option 1 is incorrect because statement (ii) is True, not False. Option 2 is incorrect because statement (i) is True, not False. Option 4 is incorrect because statements (i) and (ii) are True, not False.

  7. PYQ #47 · 2023 · DSSSB TGT Computer Science

    Which of the following commands is used to comment multiple lines in an XML file?

    1. A. /* This XML file contains a list of custom information */ then // This is a multi-line XML comment
    2. B. // then <-- This XML file contains a list of custom information --> then // then <-- This is a multi-line XML comment
    3. C. '--> then <!-- This is a multi-line XML comment (incomplete)
    4. D. <!-- This is a multi-line XML comment -->

    Correct answer: D. <!-- This is a multi-line XML comment -->

    Explanation (workbook): Core Concept: In XML, comments are enclosed within `<!--` and `-->`. This syntax allows for both single-line and multi-line comments. Any text placed between these tags will be ignored by an XML parser.

    Why other options are incorrect: Options 1, 2, and 3 use incorrect syntax for XML comments. `/* ... */` and `//` are used for comments in languages like C/C++/Java and JavaScript, respectively, but not in XML. The `-->` at the beginning or an incomplete tag makes the syntax invalid for XML comments.

  8. PYQ #61 · 2024 · DSSSB TGT Computer Science

    Which of the following rule is needed to be followed while declaring the XML (Extensible Markup Language) elements name?

    1. A. Name must start with a number
    2. B. Name can contain spaces
    3. C. Name must not start with the letter xml
    4. D. Name cannot contain letter, numbers and other characters

    Correct answer: C. Name must not start with the letter xml

    Explanation (workbook): Core Concept: According to XML naming rules, element names (and other names) cannot start with the letters 'xml' (in any case combination, e.g., XML, Xml, xML, etc.) because these are reserved for XML itself and its related specifications.

    Why other options are incorrect: XML names cannot start with a number and cannot contain spaces. XML names can contain letters, numbers, and other characters (like hyphens, underscores, periods) after the initial character.
