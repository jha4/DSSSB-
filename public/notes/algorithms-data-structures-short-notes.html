Data Structures and Design & Analysis of Algorithms — Complete Notes

Coverage: Algorithm properties, complexity, searching, sorting, recursion, stack, queue, linked lists, trees, graphs, divide-and-conquer, greedy and dynamic programming.

1. Algorithms and problem solving

An algorithm is a finite, ordered and unambiguous sequence of steps that transforms valid input into output and terminates. It has defined inputs/outputs, definiteness, finiteness and effective steps.

  • Pseudocode: language-independent logic description. Flowchart: graphical representation using standard symbols. Top-down design: decomposes a problem into smaller modules.
  • Correctness: the algorithm returns the required result for every valid input. Termination and loop invariants are common proof tools.

2. Time and space complexity

Time complexity estimates how operation count grows with input size n; space complexity estimates memory use. Big-O is an asymptotic upper bound, Big-Ω a lower bound and Big-Θ a tight bound.

ClassTypical interpretation
O(1)Constant
O(log n)Logarithmic; often halves search space
O(n)Linear scan
O(n log n)Efficient comparison sorting
O(n²)Nested loops / simple quadratic sorts
O(2ⁿ), O(n!)Exponential / factorial growth

Best, average and worst cases describe different input conditions. Complexity is not measured execution time; hardware and implementation also matter.

4. Recursion and design paradigms

  • Recursion: a function solves a problem by calling itself on smaller input. It needs a base case and progress toward that case; calls use a stack.
  • Divide and conquer: divide into subproblems, solve recursively and combine results (merge sort).
  • Greedy: make a locally best choice at each step; correctness requires a greedy-choice property (e.g. Kruskal or Prim for MST).
  • Dynamic programming: stores solutions to overlapping subproblems when optimal substructure exists; uses memoization or tabulation.

For T(n)=aT(n/b)+f(n), the Master Theorem compares f(n) with n^(log_b a); verify the theorem's conditions before using a case.

5. Core data structures

  • Array: contiguous indexed storage; O(1) random access, but middle insertion/deletion usually shifts elements.
  • Linked list: nodes hold data and links. Singly linked lists point forward; doubly linked lists point both ways; circular lists link tail to head.
  • Stack: LIFO; push, pop and peek. Used for recursion and expression evaluation. Queue: FIFO; enqueue and dequeue. Circular queues reuse array space; priority queues remove by priority.
  • Tree: hierarchy. Binary tree has at most two children per node. A BST orders keys so left subtree values are smaller and right subtree values larger under its ordering convention.
  • Graph: vertices and edges; may be directed/undirected and weighted/unweighted. Adjacency matrix uses O(V²) space; adjacency lists are efficient for sparse graphs.

6. Graph algorithms

  • BFS: explores by distance layers using a queue; finds shortest paths in unweighted graphs.
  • DFS: explores deeply using recursion or a stack; useful for components, cycle checks and topological sorting.
  • Dijkstra: single-source shortest paths with non-negative weights. Bellman–Ford: permits negative edges and detects reachable negative cycles.
  • Minimum spanning tree: connects all vertices with minimum total edge weight in a connected undirected weighted graph. Kruskal sorts edges; Prim grows a tree from a start vertex.

7. Exam traps

  • Binary search requires sorted input. BFS, not ordinary DFS, finds shortest paths in unweighted graphs.
  • Quick sort has a quadratic worst case; merge sort remains O(n log n).
  • Stack is LIFO; queue is FIFO. Big-O is an upper bound, not automatically the exact or average complexity.
