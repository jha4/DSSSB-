PART I — DESIGN & ANALYSIS OF ALGORITHMS

1. Problem solving and algorithm fundamentals

Algorithm: A finite, ordered sequence of precise and unambiguous steps that accepts valid input, produces the required output and terminates. It describes the solution logic independently of a particular programming language.

Characteristics of an algorithm

  • Input: zero or more clearly specified input values.
  • Output: at least one result related to the problem.
  • Definiteness: every instruction is clear and unambiguous.
  • Finiteness: execution terminates after a finite number of steps.
  • Effectiveness: each operation is basic enough to be carried out exactly in finite time.
  • Generality: solves a class of valid problem instances, not merely one hard-coded example.

Program-design workflow

  1. Understand the problem and constraints.
  2. Identify inputs, outputs and assumptions.
  3. Break the problem into modules (top-down design).
  4. Choose suitable data structures and an algorithm.
  5. Write pseudocode or a flowchart.
  6. Dry-run with normal, boundary and invalid cases.
  7. Implement, test, debug and refine.

Pseudocode is a language-independent, structured description of logic. It has no single mandatory syntax. A flowchart is a graphical representation of control flow.

Flowchart shapeMeaning

Top-down design: starts with the overall problem and repeatedly decomposes it into smaller subproblems. Modular programming divides a program into cohesive, manageable modules with defined interfaces.

2. Analysis of algorithms and asymptotic notation

Analysis of algorithms estimates how resource requirements grow as input size n grows. It normally counts elementary operations and memory rather than measuring seconds on one particular computer.

  • Time complexity: growth in the number of operations as a function of input size.
  • Space complexity: memory required as input size grows. Auxiliary space is the extra memory used beyond the input representation.
  • Best case: least work among inputs of size n.
  • Average case: expected work under a stated input distribution.
  • Worst case: maximum work over inputs of size n.

Asymptotic notations

NotationMeaningFormal intuition
O(g(n))Upper boundf(n) is eventually no greater than a constant multiple of g(n).
Ω(g(n))Lower boundf(n) is eventually at least a positive constant multiple of g(n).
Θ(g(n))Tight boundBoth O(g(n)) and Ω(g(n)) hold.
o(g(n))Strict upper boundf grows strictly slower than g asymptotically.
ω(g(n))Strict lower boundf grows strictly faster than g asymptotically.

Example: 3n² + 5n + 7 = Θ(n²). Constants and lower-order terms do not affect the asymptotic class. Big-O is not automatically synonymous with worst case: state the case being analysed separately.

Common growth order

GrowthTypical example
O(1)Array element access by index
O(log n)Binary Search
O(n)Linear scan
O(n log n)Merge Sort; average Quick Sort
O(n²)Simple nested loops; Bubble/Selection Sort
O(n³)Three nested linear loops; basic matrix multiplication
O(2ⁿ)Some exhaustive subset searches
O(n!)Exhaustive permutations

For sufficiently large n, a typical increasing order is O(1), O(log n), O(n), O(n log n), O(n²), O(n³), O(2ⁿ), O(n!).

Loop-analysis shortcuts

  • A single loop that increments i by 1 up to n: O(n).
  • Two nested loops each running n times: O(n²).
  • A loop that doubles i each iteration: O(log n).
  • Consecutive loops add their costs; retain the dominant term.
  • Nested loops multiply iteration counts only when their bounds behave independently as assumed. Read the actual update and bounds carefully.

Recurrence relations and Master Theorem

Recursive algorithms can be analysed using recurrences. For T(n) = aT(n/b) + f(n), compare f(n) with nlogba. The basic Master Theorem cases are: (1) f is polynomially smaller → Θ(nlogba); (2) same order up to logarithmic factors → add one logarithmic factor; (3) f is polynomially larger and the regularity condition holds → Θ(f(n)). Check the theorem's conditions before applying it.

3. Searching algorithms

Linear Search

Checks elements sequentially until the key is found or the collection ends. It works on unsorted data. Best case O(1), average/worst case O(n); iterative auxiliary space O(1).

Binary Search

Requires sorted data and efficient access to the middle element. Compare the key with the middle value and discard half the remaining search interval each iteration. Time is O(log n); iterative auxiliary space is O(1), while a recursive implementation uses O(log n) call-stack space.

FeatureLinearBinary

Worst timeO(n)O(log n)

For n elements, binary search needs approximately ⌊log₂ n⌋ + 1 comparisons in a worst-case successful search under common counting conventions; exact maximum counts depend on whether the final unsuccessful comparison is included.

4. Sorting algorithms

Sorting arranges records according to a key. A stable sort preserves the relative order of equal-key records. An in-place sort uses little auxiliary memory, though definitions allow small implementation-specific overhead.

AlgorithmBestAverageWorstStable?Key idea
BubbleO(n)*O(n²)O(n²)YesSwap adjacent out-of-order elements
SelectionO(n²)O(n²)O(n²)Usually noSelect minimum and place it next
InsertionO(n)O(n²)O(n²)YesInsert each next item into sorted prefix
MergeO(n log n)O(n log n)O(n log n)YesDivide, sort halves, merge
QuickO(n log n)O(n log n)O(n²)NoPartition around pivot
HeapO(n log n)O(n log n)O(n log n)NoRepeatedly remove heap root
RadixO(d(n+b))O(d(n+b))O(d(n+b))Usually yes with stable digit sortSort by digits/positions

*Optimized Bubble Sort with a swap flag has O(n) best case. Standard unoptimized Bubble Sort still performs O(n²) comparisons.

  • Bubble: after each pass, a largest remaining item moves to the end. Worst-case comparisons are n(n−1)/2.
  • Selection: pass i selects the smallest remaining element. It performs O(n²) comparisons but only O(n) swaps.
  • Insertion: maintains a sorted prefix; efficient for small or nearly sorted inputs.
  • Merge: predictable O(n log n), stable, but array implementation generally needs O(n) extra memory.
  • Quick: expected/average O(n log n), worst O(n²) with highly unbalanced partitions. Pivot strategy affects performance.
  • Heap: uses a binary heap; in-place array implementations use O(1) auxiliary space and are not stable.
  • Radix: non-comparison sort; complexity depends on number of digit positions and the stable per-digit method.

5. Recursion and algorithm design paradigms

Recursion occurs when a function solves a problem by calling itself on a smaller instance. A correct recursive design needs a base case, progress toward the base case and a valid combination of sub-results. Each active call occupies stack space.

  • Divide and Conquer: divide into smaller independent subproblems, solve them recursively and combine results. Examples: Merge Sort, Quick Sort and Binary Search.
  • Greedy: make a locally optimal choice at each step. It is correct only when the problem has the required greedy-choice property and optimal substructure. Examples: Huffman coding, Prim and Kruskal.
  • Dynamic Programming: solve overlapping subproblems once and store results; use memoization (top-down) or tabulation (bottom-up). Common examples: Fibonacci, LCS and 0/1 Knapsack.
  • Backtracking: build a candidate incrementally and abandon a partial candidate when it cannot lead to a valid solution. Examples: N-Queens and Sudoku.
  • Branch and Bound: explores a search tree while using bounds to prune branches that cannot improve the current best solution.
  • Randomized algorithms: use random choices; analyse expected runtime and/or probability of error. Randomized does not mean automatically incorrect.

6. Graph algorithms — syllabus-level essentials

A graph G = (V,E) consists of vertices and edges. It may be directed/undirected, weighted/unweighted, connected/disconnected. Degree counts incident edges; in directed graphs distinguish in-degree and out-degree.

RepresentationSpaceBest suited to
Adjacency matrixO(V²)Dense graphs and constant-time edge lookup
Adjacency listO(V+E)Sparse graphs and iterating neighbours
  • BFS: visits vertices level by level using a queue. With adjacency lists, O(V+E). Finds shortest paths in unweighted graphs.
  • DFS: explores a path deeply before backtracking, using recursion or an explicit stack. With adjacency lists, O(V+E). Useful for connected components, cycle detection and topological ordering.
  • Dijkstra: single-source shortest paths for non-negative edge weights. A common binary-heap implementation is O((V+E) log V); simpler matrix implementation is O(V²).
  • Bellman–Ford: handles negative edge weights and detects reachable negative cycles; O(VE).
  • Floyd–Warshall: all-pairs shortest paths; O(V³) time and O(V²) space.
  • Minimum Spanning Tree: a minimum-weight set of edges connecting every vertex of a connected, undirected, weighted graph without cycles. Prim grows one tree; Kruskal adds lightest safe edges using cycle checks/Disjoint Set Union.
  • Topological sort: linear ordering of vertices in a directed acyclic graph (DAG), where every directed edge goes from earlier to later.

PART II — DATA STRUCTURES

7. Data-structure fundamentals and ADT

A data structure organizes data so operations such as access, insertion, deletion and search can be performed efficiently. An Abstract Data Type (ADT) specifies the values and permitted operations, not the internal representation.

ClassificationTypes / examples
PrimitiveInteger, character, Boolean, floating-point
Non-primitiveArrays, lists, stacks, queues, trees, graphs
LinearArray, linked list, stack, queue
Non-linearTree, graph
Static-sizeFixed-size array (in the usual introductory model)
DynamicLinked structures and dynamically resized collections

8. Arrays, multidimensional arrays and sparse matrices

An array stores same-type elements in contiguous memory and supports O(1) indexed access. Insertion/deletion in the middle or beginning usually requires shifting elements, giving O(n) time. A two-dimensional array is logically a table; a jagged array has rows of different lengths.

Address calculation

Let BA be the base address, w the bytes per element, and indices be zero-based.

1D: LOC(A[i]) = BA + w × i
2D row-major A[M][N]: LOC(A[i][j]) = BA + w × (iN + j)
2D column-major A[M][N]: LOC(A[i][j]) = BA + w × (jM + i)
3D row-major A[L][M][N]: LOC(A[i][j][k]) = BA + w × (iMN + jN + k)

For non-zero lower bounds, subtract the relevant lower bound from each index before applying the formula. Always verify whether the question uses zero-based or one-based indexing.

Sparse matrix: a matrix in which most entries are zero. Store only non-zero values and their row/column positions (e.g. triplet representation) to save memory. A tridiagonal matrix has non-zero entries only on the main diagonal and the diagonals immediately above and below it.

9. Linked Lists

A linked list is a dynamic linear structure made of nodes. A node contains data and one or more links. Nodes need not occupy adjacent memory locations.

TypeNode linksKey property
Singly linkedNext pointerForward traversal only
Doubly linkedPrevious and next pointersForward and backward traversal
Circular singlyLast node links to firstNo NULL at the tail in a circular representation
Circular doublyPrevious and next links are circularBidirectional circular traversal
  • Access/search by position: O(n).
  • Insert/delete at head: O(1).
  • Insert/delete after a known node: O(1) pointer updates; finding the node may still take O(n).
  • Advantages: dynamic size and no shifting of all later elements on insertion/deletion.
  • Disadvantages: extra pointer memory, no O(1) random indexing, pointer manipulation and cache-locality overhead.

10. Stacks and expression processing

A stack is a linear ADT that follows LIFO (Last In, First Out). Insertion and deletion occur at the top.

OperationMeaningTypical time
push(x)Insert x at topO(1)
pop()Remove and return topO(1)
peek/top()Read top without removingO(1)

Overflow occurs when pushing onto a full bounded stack; underflow occurs when popping/peeking an empty stack. Linked-list stacks can grow until memory is exhausted.

Applications: function-call/recursion management, parentheses matching, undo, DFS, backtracking, infix-to-postfix conversion and postfix evaluation.

NotationOperator positionExample
InfixBetween operandsA + B
PrefixBefore operands+ A B
PostfixAfter operandsA B +

Postfix evaluation: scan left to right; push operands; when an operator appears, pop the required operands in the correct order, evaluate and push the result. For a binary operator, the first pop is the right operand and the second pop is the left operand.

11. Queues and their variants

A queue is a linear ADT that normally follows FIFO (First In, First Out). Enqueue inserts at the rear; dequeue removes from the front.

TypeInsertion / deletionUse
Simple queueRear / frontBasic FIFO processing
Circular queueRear / front with wrap-aroundReuses freed array positions
DequeBoth endsDouble-ended operations
Priority queueRemoval by priorityScheduling, shortest-path algorithms

In a circular array of capacity N, the next index is commonly (index + 1) mod N. A queue can be implemented using arrays or linked lists. BFS uses a queue.

12. Trees and binary trees

A tree is a hierarchical, connected acyclic structure. The root has no parent; a leaf has no children. A node's degree is its number of children. Depth is distance from root; height is the length of the longest downward path to a leaf (some texts count edges, others count nodes—follow the question's convention).

  • Binary tree: each node has at most two children.
  • Full/strict binary tree: every node has either zero or two children.
  • Complete binary tree: all levels except possibly the last are full, and the last level is filled from left to right.
  • Perfect binary tree: every internal node has two children and all leaves are at the same level.

For a binary tree of height h measured in edges, maximum nodes = 2h+1 − 1 and minimum nodes = h + 1 for a non-empty tree. If height is counted in levels, formulas shift by one; read the convention carefully.

Tree traversals

TraversalOrder
PreorderRoot → Left → Right
InorderLeft → Root → Right
PostorderLeft → Right → Root
Level orderLevel by level using a queue

Binary Search Tree (BST)

For the standard distinct-key BST convention, keys in the left subtree are smaller than the node and keys in the right subtree are larger. Inorder traversal yields ascending order. Search/insert/delete take O(h), where h is tree height: O(log n) when balanced and O(n) in the worst skewed tree.

Deletion cases: (1) leaf — remove it; (2) one child — link parent to the child; (3) two children — replace with inorder successor (minimum in right subtree) or inorder predecessor (maximum in left subtree), then delete that replacement node.

AVL Trees

An AVL tree is a self-balancing BST. Balance factor = height(left) − height(right). Every node must have balance factor −1, 0 or +1. Rotations restore balance:

ImbalanceCorrection
LLSingle right rotation
RRSingle left rotation
LRLeft rotation on left child, then right rotation
RLRight rotation on right child, then left rotation

13. Heaps and priority queues

A binary heap is a complete binary tree satisfying a heap-order property. In a max heap, each parent is at least as large as its children; in a min heap, each parent is at most as large as its children. It is not necessarily a fully sorted tree.

  • For zero-based array indexing: parent(i) = floor((i−1)/2), left(i) = 2i+1, right(i) = 2i+2.
  • Peek root: O(1). Insert: O(log n) by sift-up. Remove root: O(log n) by sift-down. Build-heap: O(n).
  • Heaps implement priority queues and Heap Sort.

14. Hashing

Hashing maps a key to a table index using a hash function. A collision occurs when two different keys map to the same index. A good hash function distributes keys uniformly.

Division method: h(k) = k mod m, where m is table size. Example: if m = 9, h(22) = 4.

Collision methodHow it works
Separate chainingEach table slot stores a list/bucket of colliding keys.
Linear probingTry next slots sequentially: (h(k)+i) mod m.
Quadratic probingUse quadratic offsets, e.g. h(k)+c₁i+c₂i².
Double hashingUse a second hash function to determine the probe step.

Load factor α = number of stored keys / table capacity. Open addressing performance generally degrades as load factor approaches 1. Deletion in open addressing often requires a special deleted marker to preserve probe chains.

15. Graph data structures and miscellaneous structures

Graphs are non-linear data structures consisting of vertices and edges. Common concepts: path, cycle, connected component, degree, articulation point, bridge, directed acyclic graph and weighted edge. Adjacency lists use O(V+E) space; adjacency matrices use O(V²).

Other structures worth knowing: Deque (insert/delete at both ends), Priority Queue (removal by priority), Disjoint Set Union (maintains disjoint sets using union/find), Trie (prefix tree for strings), and B-Tree/B+ Tree (multiway balanced search trees commonly used in storage/indexing). These are enrichment beyond the basic named syllabus unless directly asked in a PYQ.
