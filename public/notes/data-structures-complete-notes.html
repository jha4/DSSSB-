1. Arrays

Definition: An array is a linear, indexed data structure that stores a fixed number of elements of the same data type in contiguous memory locations. Each element is accessed using an index, usually starting at 0 in C, C++ and Java.

How an array works

  • Contiguous storage: Elements occupy consecutive memory locations. If the base address is known, the address of an element can be calculated directly.
  • Address calculation (1-D): For zero-based indexing, address(A[i]) = base(A) + i × w, where w is the size of each element in bytes.
  • Random access: Accessing A[i] takes O(1) time because the address is computed rather than found by scanning.
  • Fixed capacity: A conventional static array has a fixed size after creation. A dynamic array manages a resizable backing array, usually by allocating a larger block and copying elements when capacity is exhausted.
  • Insertion/deletion: Inserting or deleting near the beginning or middle usually requires shifting elements, so it takes O(n). At the end, append is O(1) amortised for a dynamic array, although an individual resize may take O(n).
  • Searching: Linear search is O(n). Binary search is O(log n) only when the data is sorted and efficient middle-element access is available.

Types and memory layout

  • One-dimensional array: A sequence addressed with one index, such as A[i].
  • Two-dimensional array: A table of rows and columns, accessed as A[i][j]. In C/C++, the first subscript identifies the row and the second identifies the column.
  • Jagged array: A collection of rows that can have different lengths. It is not the same as a rectangular 2-D array.
  • Row-major order: Complete rows are stored consecutively (C/C++ conventional 2-D arrays).
  • Column-major order: Complete columns are stored consecutively (used by some languages and numerical systems).

Advantages, limitations and uses

  • Fast indexed access, simple traversal and low per-element overhead.
  • Useful for tables, matrices, lookup tables, heaps, sorting and implementing stacks/queues.
  • Size changes are expensive in a static array; insertion/deletion in the middle requires shifting; unused capacity in a dynamic array can waste memory.

Complexity snapshot: index access O(1); linear search O(n); insertion/deletion at the beginning or middle O(n); traversal O(n); dynamic-array append O(1) amortised.

2. Linked Lists

Definition: A linked list is a dynamic linear data structure made of nodes. Each node stores data and one or more links (references/pointers) to other nodes. Nodes need not occupy contiguous memory locations.

Node structure and types

  • Singly linked list: Each node contains data and a next pointer. The last node points to NULL. Traversal is forward only.
  • Doubly linked list: Each node contains previous and next pointers. Traversal is possible in both directions, but each node needs extra memory.
  • Circular singly linked list: The last node points back to the first node instead of NULL.
  • Circular doubly linked list: The last node's next points to the first node and the first node's previous points to the last.
  • Header/sentinel node: An optional special node simplifies boundary operations; it may store metadata rather than user data.

Operations and complexity

  • Traversal/search: Start at the head and follow links; O(n) in the worst case.
  • Insertion at head: Set the new node's next to the old head and update head; O(1).
  • Deletion at head: Move head to head.next; O(1).
  • Insertion after a known node: Adjust links; O(1), provided the node reference is already available.
  • Deletion: In a singly linked list, the previous node is generally needed to bypass the target. In a doubly linked list, links can be updated directly when the target node is known.
  • Access by position: O(n), because the list must be traversed; there is no direct index-based random access.

Array versus linked list

Advantages: flexible size and efficient insertion/deletion when the relevant node position is known. Disadvantages: pointer overhead, sequential access, poorer cache locality and more complex pointer handling. A linked list is not automatically faster than an array; the operation pattern matters.

3. Stacks

Definition: A stack is a linear abstract data type that follows Last In, First Out (LIFO): the most recently inserted item is the first item removed.

Core operations

  • push(x): Insert x at the top.
  • pop(): Remove and return the top item.
  • peek/top(): Read the top item without removing it.
  • isEmpty(): Test whether the stack contains no elements.
  • Overflow: Push attempted on a full fixed-capacity array stack.
  • Underflow: Pop/peek attempted on an empty stack.

Push, pop and peek are O(1) in a conventional implementation. A stack can be implemented using an array or linked list. In an array implementation, a top index tracks the current top; in a linked-list implementation, insertion and deletion usually occur at the head.

Applications

  • Function calls, recursion and call-stack frames.
  • Expression conversion and evaluation: infix, prefix and postfix.
  • Parenthesis matching, syntax parsing, undo operations and backtracking.
  • Depth-first search (DFS) can use an explicit stack; recursive DFS uses the program call stack.

Expression notation

  • Infix: operator between operands, e.g. A + B.
  • Prefix (Polish): operator before operands, e.g. + A B.
  • Postfix (Reverse Polish): operator after operands, e.g. A B +.
  • Postfix evaluation scans left to right: push operands; when an operator appears, pop the required operands, apply the operator and push the result. Operand order matters for subtraction and division.

4. Queues

Definition: A queue is a linear abstract data type that follows First In, First Out (FIFO): the earliest inserted element is removed first.

Operations and variants

  • enqueue: Insert at the rear.
  • dequeue: Remove from the front.
  • front/peek: Read the next element to be removed.
  • Simple queue: Insert at rear and delete at front.
  • Circular queue: Treats the array as circular; indices wrap using modulo capacity, preventing wasted space at the beginning.
  • Deque: Double-ended queue; insertion and deletion are permitted at both ends.
  • Priority queue: Removal is based on priority, not simply arrival order. A heap is a common implementation.

Enqueue and dequeue can both be O(1) when front/rear pointers are maintained correctly. A naive array queue that does not reuse freed positions may suffer false overflow; a circular queue addresses this.

Applications

  • CPU and printer scheduling, buffering, producer-consumer systems and breadth-first search (BFS).
  • Message queues and requests waiting for a service.
  • In BFS, a queue ensures vertices are processed in non-decreasing distance (number of edges) from the start vertex in an unweighted graph.

5. Trees, Binary Trees, BST and AVL Trees

Definition: A tree is a connected, acyclic hierarchical data structure consisting of nodes and edges. The top node is the root. A node may have children; a node with no children is a leaf.

Tree terminology

  • Parent/child: Direct predecessor/successor in the hierarchy.
  • Siblings: Nodes with the same parent.
  • Ancestor/descendant: Nodes above/below another node along a path.
  • Degree of a node: Number of its children. Degree of a tree is the maximum node degree.
  • Depth: Number of edges from the root to a node.
  • Height of a node: Number of edges on the longest downward path from that node to a leaf. Tree height is the root's height. Some texts count nodes rather than edges; read the convention in the question.
  • Subtree: A node together with all its descendants.

Binary tree properties

  • A binary tree has at most two children per node: left and right.
  • At level i (root at level 0), the maximum number of nodes is 2i.
  • A perfect binary tree of height h (edge-count convention) has 2h+1 − 1 nodes.
  • A binary tree with n nodes has n − 1 edges when n is positive and the tree is connected.
  • A full/strict binary tree has either zero or two children at every node. A complete binary tree fills levels from left to right, with only the last level possibly incomplete.

Binary Search Tree (BST)

A BST is a binary tree in which, under the usual distinct-key convention, every key in the left subtree is smaller than the node's key and every key in the right subtree is greater. Search, insertion and deletion take O(h), where h is tree height. A balanced BST has O(log n) height; a skewed BST can have O(n) height.

TraversalOrderCommon use

AVL trees and rotations

An AVL tree is a self-balancing BST. For every node, the balance factor is height(left subtree) − height(right subtree), and it must be −1, 0 or +1. If an insertion or deletion violates this condition, rotations restore balance.

  • LL case: Right rotation at the unbalanced node.
  • RR case: Left rotation.
  • LR case: Left rotation on the left child, then right rotation on the node.
  • RL case: Right rotation on the right child, then left rotation on the node.

LL and RR are single rotations; LR and RL are double rotations. AVL search/insert/delete are O(log n) because the height remains logarithmic.

6. Heaps and Priority Queues

Definition: A binary heap is a complete binary tree that satisfies the heap-order property. In a max-heap, each parent is greater than or equal to its children; in a min-heap, each parent is less than or equal to its children. A heap is not a binary search tree.

  • Array representation (0-based): parent(i) = floor((i−1)/2), left(i) = 2i+1, right(i) = 2i+2.
  • Insert: Place the new key at the next available leaf and sift/bubble it upward; O(log n).
  • Extract max/min: Replace the root with the last element and sift downward; O(log n).
  • Peek: Read the root; O(1).
  • Build heap: Bottom-up heap construction is O(n), not O(n log n).
  • Heap sort: Build a heap and repeatedly remove the root; O(n log n) time. Standard in-place heap sort is not stable.

Important distinction: A heap guarantees only parent-child ordering, not complete sorting of all elements. Searching for an arbitrary key is generally O(n).

7. Graphs

Definition: A graph G = (V, E) consists of a set V of vertices (nodes) and a set E of edges connecting pairs of vertices. Graphs model networks, routes, dependencies and relationships.

Types and terminology

  • Undirected graph: Edges have no direction. Directed graph (digraph): Each edge has a direction.
  • Weighted graph: Edges carry values such as cost, distance or time.
  • Degree: In an undirected graph, number of incident edges. In a digraph, distinguish indegree and outdegree.
  • Path: Sequence of vertices connected by edges. Cycle: A path that returns to its starting vertex without repeating intermediate vertices (in a simple cycle).
  • Connected graph: Every pair of vertices has a path between them. A directed graph has stronger notions of strong and weak connectivity.
  • Tree: A connected undirected acyclic graph; with n vertices it has n−1 edges.
  • Articulation point: A vertex whose removal (with its incident edges) increases the number of connected components.

Graph representations

RepresentationSpaceBest suited for
Adjacency matrixO(V²)Dense graphs; O(1) edge-existence test
Adjacency listO(V+E)Sparse graphs; efficient neighbour traversal

Graph traversal

  • BFS: Breadth-first search explores level by level using a queue. In an adjacency-list representation it takes O(V+E). It finds shortest paths by edge count in an unweighted graph.
  • DFS: Depth-first search explores as far as possible before backtracking; it uses recursion or a stack. With adjacency lists it takes O(V+E). It supports cycle detection, connected components and articulation-point algorithms.

8. Hashing

Definition: Hashing maps a key to an array/table index using a hash function h(key). A hash table supports expected O(1) insertion, search and deletion when the hash function distributes keys well and the load factor is controlled.

  • Collision: Two different keys map to the same table index.
  • Separate chaining: Each table slot stores a collection (often a linked list) of entries that hash to that slot.
  • Open addressing: All entries are stored in the table itself; on collision, probe another slot.
  • Linear probing: Try h(k), h(k)+1, h(k)+2, … modulo table size. It is simple but can cause primary clustering.
  • Quadratic probing: Probe using quadratic offsets; reduces primary clustering but may not visit every slot for every table size.
  • Double hashing: Use a second hash function to determine the probe step.
  • Load factor: α = number of stored entries / table capacity. High load factors generally increase collisions and probe lengths.

Hashing is effective for equality lookup, but does not naturally maintain sorted order or support efficient range queries. Deletion in open addressing requires care (often tombstones) so that later searches are not broken.
